# 여행 삭제 동작 검증

2026-10-26 · 로컬 구현 및 검증. 운영 여행 데이터는 변경하지 않았고, 배포하지 않았습니다.

## 동작

- 다른 참여 계정이 남아 있으면 요청 계정의 참여를 해제하고 그 계정의 목록에서 삭제합니다. 공유 일정·지출·예약·첨부파일은 유지합니다.
- 여행장이 먼저 나가면 남은 편집자 우선, 참여 순서로 소유권을 이전합니다. 마지막 열람자만 남아도 소유자로 승격합니다.
- 마지막 참여 계정이 삭제하면 서버 여행 및 FK 연결 데이터와 알림 대기 데이터를 삭제하고, Storage API로 실제 첨부파일까지 정리한 뒤 성공을 반환합니다. 초대 대기자는 인원에 포함하지 않습니다.
- 최소 작업 영수증은 응답 유실 재시도용으로 남습니다. 여행 내용은 저장하지 않습니다. 파일 삭제 실패 시 정리 작업을 유지하고 같은 요청이나 다음 목록 조회에서 재처리합니다.
- 내 목록의 마지막 여행도 삭제할 수 있습니다. 삭제 후 빈 목록을 표시하며 새 여행 만들기가 가능합니다. 기기의 삭제된 여행 내용·동기화 복구 스냅샷·초안을 제거하고, 오래 열린 탭의 재저장을 차단합니다. 사용자가 별도로 만든 수동 백업 파일이나 저장 기록을 전역 초기화하지 않습니다.
- 완전한 서버 목록만 다른 기기의 삭제된 참여를 반영합니다. 이전 서버나 잘린 목록으로는 기기 기록을 지우지 않습니다.

## 검증

- CLI 전체 회귀 검사(소스·DB·클라이언트 동기화·서비스·기능·CLI 212개 프로세스 검증·터미널) 통과. 마지막 전체 재실행도 통과했습니다. 이후 초대 재가입의 세션 확인을 강화한 한 줄 경계 변경은 삭제 클라이언트 회귀 검사와 빌드로 다시 검증했습니다.
- SQL 실제 마이그레이션을 격리 PGlite에 적용: 단독/마지막 멤버 삭제, 동행 데이터 보존, 여행장 이전, 로컬 ID 충돌, 비회원/일반 DB 역할 접근 거절, 요청 재사용 검증. PGlite의 직렬 실행 검증이며 운영 Postgres 다중 세션 부하 시험은 아닙니다.
- Deno Edge 테스트 3개 통과: 검증된 계정만 RPC 전달, 참여 삭제 후 영수증 재시도, 파일 삭제 실패/복구, 잘린 목록 보호, 삭제와 겹친 업로드 정리, 기존 인증/권한 게이트.
- 브라우저 9개 관련 스위트 통과: trip-removal, trip-chooser, transport-reservations, trip-library-views, delete-dialogs, sync-browser, sync-offline, trip-library, auth-session. Playwright/Edge, 격리 계정·SQL 서버·기기 저장소, 외부 요청 차단.
- 모바일 320/390px, 선택창 1440px, 확인창 6가지 화면 너비를 확인했습니다. 대표 캡처와 결과 JSON을 이 폴더에 보관합니다.
- 소스 검사 및 빌드 통과. 범위 격리 체크아웃의 빌드 216fb82ad30c20d68dac. root의 다른 작업에서 생성된 Travel.html/sw.js는 덮어쓰지 않았습니다. 파일별 지문은 scope.json을 참고하세요.

## 운영 반영

이 기능을 켜려면 DB 마이그레이션 supabase/migrations/20261026065147_trip_removal_lifecycle.sql → triplog-sync Edge Function → 프런트엔드 순서로 반영해야 합니다. 프런트엔드 Git 자동 배포만으로 DB·Edge Function 배포까지 완료되지는 않습니다. 현재는 모두 배포 전입니다.

Supabase 문서: [Storage 객체 삭제](https://supabase.com/docs/guides/storage/management/delete-objects). DB의 storage.objects 메타데이터를 SQL로 삭제하지 않고 Storage API를 사용합니다.
