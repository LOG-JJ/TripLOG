# 시간 선택·직접 입력 흐름 분리

사용자와 합의한 동작: 하단을 `입력 / 없음 / 확인`으로 바꾸고, `입력`을 눌렀을 때 작은 시간 선택창만 닫은 뒤 원래 시간칸에서 숫자를 입력한다. 일정·예약 편집창은 유지한다. 휠 선택과 확인으로 모바일 키보드가 열리는 동작을 없앤다.

## 구현

- 하단 버튼을 같은 높이의 세 칸으로 구성했다. 짧은 화면 문구는 `입력`, `없음`이며 접근성 이름은 `시간 직접 입력`, `시간 없음`이다. 320px에서도 모든 글자가 잘리지 않는다.
- `입력`은 현재 휠 값을 확정하고 선택창만 닫는다. 원래 시간 텍스트칸을 사용자 클릭 안에서 즉시 포커스하고 전체 선택한다. `inputmode=numeric`, `enterkeyhint=done`을 사용한다.
- 직접 입력 중 시간칸을 다시 터치해도 휠이 열리지 않는다. `1840`은 `18:40`으로 표시된다. 완료/Enter는 값을 한 번 확정하고 비편집 버튼으로 포커스를 옮긴다. 다른 칸으로 이동할 때는 폼 제출 전에 동기적으로 확정한다. Escape는 입력 전 시간으로 복귀하고 부모 편집창을 닫지 않는다.
- `확인`, `없음`, 휠 취소 후에는 텍스트칸 대신 열기 버튼으로 포커스를 돌린다. 터치로 휠 가운데 숫자를 눌러도 직접 입력으로 전환하지 않는다. 기존 PC의 마우스 중앙 편집과 키보드 직접 입력·방향키는 유지한다.
- 터치에서 발생하는 합성 mousedown의 기본 포커스 이동을 제어해 선택창이 뜻하지 않게 닫히는 현상을 막았다. 터치 스크롤은 차단하지 않는다.
- 부모 편집창을 닫거나 다른 시간 선택기를 열 때 직접 입력 상태도 종료한다.

## 환경·실제 크기

Browser 플러그인을 사용할 수 없어 기존 Playwright/Edge 격리 fixture를 사용했다. 외부 요청·서비스 워커는 차단했고 실제 계정·여행 데이터는 수정하지 않았다. 경로는 로컬 `/Travel?page=itinerary` 및 예약 지갑이다.

| 화면 | 선택창 | 표시 |
| --- | --- | --- |
| 1440×1100 PC | 169×162px | 시간·분 각각 5줄 |
| 390×844 터치 | 170×174px | 동일 |
| 320×844 터치 | 152×174px | 동일, 버튼 글자 넘침 없음 |
| 640×360 터치 | 224×174px | 동일, 화면 안에 배치 |

앞선 두 버튼 버전과 선택창 크기가 같다. 화면을 바꿀 때 열린 창도 입력칸 폭에 맞춰 다시 계산한다.

페이지 제목·초기화·편집창 표시·오류 오버레이 부재를 확인했다.
앱 런타임 오류는 없다. 콘솔의 `net::ERR_FAILED`와 서비스 워커 차단 경고는 테스트 격리 설정에서 발생했으며 `after-metrics.json`에 수집했다.

실제 iPhone·Android의 OS 키보드는 이 Windows 테스트에서 표시되지 않는다. 따라서 확인한 것은 실제 터치 이벤트에서의 DOM 포커스·입력·선택창 동작이며, 실제 기기의 키보드 표시/숨김·iOS 화면 확대는 별도 검증하지 않았다. `direct-input-mobile.png`는 입력 중인 시간칸 캡처이며 OS 키보드 캡처가 아니다.

캡처 복사본은 SHA256으로 원본과 대조했고 `verification.json`에 기록했다. 전체 임시 스크립트·출력은 `artifacts/tmp/20261026-time-input-mode/`에 있다. 로컬 구현·검증·빌드 완료이며, 이번 변경은 커밋·푸시·운영 배포하지 않았다.
