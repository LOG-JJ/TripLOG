# 모바일 지출 구성·기본 결제자 이름 수정

2026-11-01 · Asia/Seoul

사용자는 모바일 지출 구성에서 잘리는 항목명을 수정하고 2행 3열로 표시하며, JH로 설정했는데 결제자에 여행 대표가 뜨는 문제를 고치도록 요청했다.

## 지출 구성

- 모바일에서 2열로 바꾸던 미디어 규칙을 제거하고 3열로 통일했다. 6개 분류는 위 3개·아래 3개다.
- 항목명에 색 점과 두 글자가 들어갈 최소 너비를 확보했다. 백분율은 오른쪽 한 줄에 표시한다. 긴 `1% 미만`은 화면에서 `<1%`로 표시하고 버튼의 접근성 설명·구성 막대 설명에는 기존 의미를 유지한다.
- 44px 터치 높이와 항목별 지출 내역 이동을 유지했다. 금액·비율·분류 순서 계산은 변경하지 않았다.
- 실제 [320px](cost-six-categories-320.png), [390px](cost-six-categories-390.png), [320px 확대 글자](cost-six-categories-320-large-text.png)에서 3열·2행과 한 줄 전체 항목명, 이름/비율 겹침 및 넘침이 없는 것을 확인했다.

## 결제자 이름

- 기존 목록은 `state.settlement.leaderName`에 들어 있는 기본 문자열 `여행 대표`를 그대로 사용해 프로필 이름이 JH여도 별도로 표시했다.
- 공통 표시 이름 함수를 추가했다. 직접 저장한 정산 이름이 있으면 그것을 우선하고, 기본값이면 실제 여행장 계정의 프로필 또는 여행 멤버의 여행장 이름을 사용한다. 어느 쪽도 확인되지 않을 때만 여행 대표를 표시한다.
- 현재 계정이 여행장과 같은 ID인지 확인해 프로필을 사용한다. 다른 동행이 볼 때 그 동행의 프로필로 여행장을 바꾸지 않는다. 실제 여행장 이름을 찾을 수 있는 경우 해당 멤버 이름을 사용한다.
- 결제자 목록·정산·분담 입력에서 공통 `getSettlementMembers()`를 통해 같은 이름을 사용한다. 정산 이름 편집창도 같은 표시 이름을 입력값으로 사용하되, 충돌 검사 기준은 원래 저장값으로 유지한다.
- [기본 결제자 JH 확인](profile-payer-JH-390.png). 결제자 키 `leader`, 저장된 결제자 연결·지출·분담액을 바꾸지 않고 표시만 해결한다. 페이지 표시만으로 공유 정산 이름을 자동 저장하지 않는다.

## 검사

- `travel-costs-browser-regression.js` 통과: 320/390/430px에서 일반·16px 확대 글자, 실제 그리드 3열·2행, 전체 이름 표시·한 줄·비율과 겹침 없음, 필터/키보드 연결, 기존 경비 계산·환불·사전구매·재로드·큰 금액·안전한 미지정 분류를 확인했다.
- `settlement-name-browser-regression.js` 통과: 프로필 JH 기본 표시, 지출 수정의 결제자 JH, 고정 키 보존, 수동 정산 별칭 우선·저장/취소/실패/재로드, 다른 여행장·이름 미확인 시 안전한 기본값, 권한·동시 수정, 다른 여행 및 돈/분담 보존을 확인했다.
- `expense-allocation-browser-regression.js` 통과: 기존 금액/비율 분담·정산·저장 실패/재시도·외화·변경 감지·모바일/PC 동작을 확인했다.
- `dev test --suite source --json`, `dev build --json` 통과. 새 DB 필드·마이그레이션·서버 함수·의존성을 추가하지 않았다.

실제 Edge/Playwright의 독립 fixture 계정과 여행으로 검증했으며 사용자 브라우저나 운영 여행 데이터를 수정하지 않았다. 기존 인앱 브라우저 핸들이 `browser.user is unavailable`을 반환해 프로젝트가 허용한 격리 브라우저 경로를 사용했다. 현재 로컬 소스와 빌드에 반영했고 Git 푸시·운영 배포는 하지 않았다. 캡처 원본·보존본 SHA256은 [보존 기록](capture-provenance.json)에 남겼다.
