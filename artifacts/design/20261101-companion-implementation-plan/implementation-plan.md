# TripLOG 목업 기반 통합 구현 계획

작성일: 2026-11-01 · Asia/Seoul  
상태: 이후 사용자의 `구현해줘` 요청에 따라 로컬 앱에 구현했다. 아래 내용은 구현 기준을 보존한 계획이며, 실제 실행 결과와 제한은 [구현 QA](../../qa/20261101-companion-redesign/design-qa.md)에 기록한다. 운영 여행 데이터 수정·Git 푸시·배포는 실행하지 않았다.

## 1. 구현 목표와 범위

**오늘의 여행 → 예약 확인 → 지출 기록 → 준비물/파일 저장 → 일정 분석**이 같은 여행·날짜·항목을 기준으로 이어지게 만든다. 화면마다 정보를 새로 복제하지 않고 기존 일정·예약·지출 원본을 조회해 보여준다.

이번 통합 작업의 중심은 오늘의 여행, 예약 지갑, 여행 도구, 일정 분석이다. 기존 일정 요약·편집 화면의 로컬 수정은 보존하고 공통 시간·이동·아이콘·연결 동작을 재사용한다. 구현은 단계별로 완성하되 최종적으로 한 묶음의 일관된 경험을 만든다.

| 영역 | 구현할 결과 | 범위 경계 |
| --- | --- | --- |
| 오늘의 여행 | 다음 장소, 진행 조작, 예약/숙소 바로가기, 빠른 지출, 이후 일정 | 실제 위치 추적·자동 방문 완료·자동 시간 조정 없음 |
| 예약 지갑 | 오늘 필요한 예약, 날짜별 목록, 상세/편집, 일정·지출 연결 | 결제 대시보드·신규 파일 업로드 없음 |
| 여행 도구 | 준비물 우선, 오프라인 정보 파일, ICS 파일, 시간대 | 캘린더 계정 연동·날씨·주변검색 추가 없음 |
| 일정 분석 | 날짜별 시간 비교, 장소별 순위, 날짜 상세, 미입력 진입 | 계획 데이터 분석이며 실제 활동 시간으로 표현하지 않음 |
| 일정 점검 | 사용 중인 메뉴·탭·진입 제거 | 기존 데이터와 호환 함수는 사용처 확인 후 정리 |
| 기존 일정 요약 | 현재 로컬 구현을 기준으로 연결·회귀 확인 | 이미 만든 화면을 다시 제작하지 않음 |

## 2. 어떤 목업을 따를 것인가

사용자의 최신 요구가 생성 이미지의 장식·문구보다 우선한다. 새 목업이 이전 목업 전체를 자동 승인하거나, 이미지 안의 예시 기능을 추가하라는 뜻은 아니다.

| 묶음 | 계획의 시각 기준 | 현재 선택 상태 |
| --- | --- | --- |
| 오늘의 여행 | [기본 화면](../20261031-today-trip-interactions/reference.png), [완료·건너뛰기·시작](../20261031-today-trip-interactions/progress-actions.png), [빠른 지출](../20261031-today-trip-interactions/quick-expense.png), [누락·완료·여행 전후](../20261031-today-trip-interactions/supporting-states.png) | 사용자가 keep 확정 |
| 예약 지갑 메인 | [숙소 대표 카드를 제거한 최신안](../20261031-wallet-selected-refinement/refined-wallet.png) | 최신 요구를 반영한 계획 기준안 |
| 예약 상세/입력 | [종류별 상세](../20261031-wallet-detail-add-states/detail-variants.png), [추가/편집](../20261031-wallet-detail-add-states/add-variants.png), [보조 상태](../20261031-wallet-detail-add-states/supporting-states.png) | 하나의 공통 창에 종류별 필드 적용 |
| 예약 지출 연결 | [편집 안의 작은 연동 영역과 기존 지출 선택](../20261031-wallet-expense-companion/expense-link-flow.png) | 최신의 간결한 구성을 우선 |
| 여행 도구 | [메인·준비물·저장 옵션](../20261031-travel-tools-itinerary-analysis/travel-tools-mobile.png) | 계획 기준안, 세부 표현 조정 가능 |

| PC | [여행 도구·일정 분석](../20261031-travel-tools-itinerary-analysis/desktop-companion.png) | 모바일과 동일한 정보의 넓은 배치 |

원본 파일 목록은 [mockup-index.json](mockup-index.json)에 보관한다. 오늘의 여행 외 묶음을 승인 완료로 바꾸지는 않는다. 이 계획에서는 최신 후보를 기준으로 실제 구현 범위를 구체화한다.

과거의 결제 중심 예약 메인, 숙소를 상단에 고정한 지갑, 큰 일정 다듬기 버튼, 주변검색은 채택하지 않는다. 일정 요약의 편집 버튼은 최신 요청대로 메타 행 우측의 작은 연필을 유지한다. 목업의 휴대폰 프레임·상태바·예시 키보드·알림 아이콘은 새 기능 요구가 아니다.

## 3. 현재 코드와의 차이

다음은 로컬 소스를 읽어 확인한 내용이며 운영 배포 상태를 뜻하지 않는다.

| 현재 소스/동작 | 필요한 변경 |
| --- | --- |
| `travel-companion/workspace.js`가 오늘·점검·예약·도구를 한 파일에서 렌더링 | 기존 진입 API는 유지하면서 화면 렌더링과 상태 조작을 기능별로 나눔 |
| `model.today()`는 항상 첫 미완료 항목을 선택 | 명시적으로 선택한 진행 위치와 건너뛰기를 반영하는 선택 규칙 추가 |
| 방문 완료가 `completedItineraryIds`에 저장되고 sync progress 엔티티로 공유됨 | 기존 공유 의미를 보존하고 개인 진행 위치와 분리 |
| 오늘 화면 진입은 여행 종료 뒤에도 첫날로 기본 설정될 수 있음 | 이미 있는 `defaultItineraryDate()`를 공통 사용해 첫날/오늘/마지막 날 선택 |
| 예약 목록이 검색 결과의 첫 항목을 대표 카드로 표시 | 당일의 숙소 외 예약을 선별하고 미래/지난/숙소 일반 목록을 구분 |
| 예약은 manual/entry/itinerary 세 출처를 합쳐 표시 | 출처와 원본 ID를 유지하는 통합 조회·편집·연결 계층 필요 |
| 수동 예약 정규화는 명시된 필드만 보존 | 티켓 URL·인원·좌석·지출 연결 등을 정규화/검증/백업까지 확장 |
| 사전구매 항공 예약 한 행에 가는 날·오는 날이 함께 저장될 수 있음 | 왕복 이용 회차를 표시용으로 나눠 당일 귀국편도 조회, 지출은 동일 원본 유지 |
| 도구는 큰 표지와 파일 저장이 먼저, 준비물은 아래 | 준비물 우선의 간결한 도구 메인으로 재배치 |
| 준비물 전체 편집 창과 도구 내부 체크 목록이 별도로 존재 | 동일 원본·명령·행 컴포넌트를 사용해 두 화면의 상태를 일치시킴 |
| 일정 분석은 날짜 필터·세 지표·장소 막대 목록 중심 | 공통 집계 모델, 날짜별 비교, 미입력 목록과 편집 복귀 추가 |
| 일정 요약의 다중 이동/미입력 입력·작은 연필은 로컬에 구현됨 | 새 화면에서 해당 편집기와 인접 구간 규칙을 재사용 |

현재 변경 중인 README, Travel.html, sw.js, 일정 요약·이동 편집·브라우저 테스트와 fixture는 보존한다. 이후 구현 시작 때 그 시점의 diff와 테스트 기준을 다시 확인한다.

## 4. 화면 구조와 이동

하단의 개요·일정·지출·리포트·설정은 유지한다. 오늘의 여행·예약 지갑·여행 도구는 일정 메뉴에서, 일정 분석은 리포트에서 접근한다. 일정 점검을 없앤 자리에 새 조정 기능을 넣지 않는다.

| 출발 | 동작 | 도착 및 복귀 |
| --- | --- | --- |
| 일정 메뉴 | 오늘의 여행 / 예약 지갑 / 여행 도구 | 기존 companion 진입을 통해 열기, 닫으면 원래 일정 위치 |
| 리포트 | 일정 분석 | 지출 분석과 같은 탭 구조 |
| 오늘의 여행 | 장소 연필 / 이후 일정 | 기존 일정 편집기, 저장·취소 후 해당 날짜/항목으로 복귀 |
| 오늘의 여행·예약 지갑 | 예약 상세 | 같은 예약 상세 창, 뒤로 가면 원래 목록/스크롤 |
| 오늘의 여행 | + 지출 | 기존 지출 입력의 간편 모드, 저장 후 오늘 화면 갱신 |
| 예약 편집 | 기존 지출 연결 / 기존 일정 연결 | 선택 창 → 원래 작성 중인 폼, 취소 시 작성값 유지 |
| 일정 분석 | 날짜 막대 / 미입력 / 장소 | 날짜 상세 또는 기존 시간·이동 편집기 → 필터·정렬·스크롤 유지 |
| 여행 도구 | 준비물 전체 / 오프라인 저장 | 같은 도구 화면 안의 상세 또는 공통 dialog |

기존 review 호출이 남아 있으면 일정 분석으로 안내하는 호환 진입을 두고, UI·이벤트·테스트 사용처를 정리한다. 모달 안에 별도의 하단 탐색을 또 쌓지 않는다. 공통 dialog의 포커스 복원과 기존 내비게이션의 뒤로 가기 동작을 사용한다.

## 5. 공통 디자인·컴포넌트

흰 바탕, 남색 글씨/선, 노란 주요 버튼, 연한 파랑·분홍 보조색, 작은 오프셋 그림자를 현재 디자인 토큰에 맞춰 사용한다. 크림색/연노랑 전체 바탕으로 되돌리지 않는다. 주요 동작의 노랑은 유지한다.

| 공통 요소 | 재사용 위치 | 구현 기준 |
| --- | --- | --- |
| 여행·Day·날짜 맥락 행 | 네 화면 | 이름·기간·선택일을 실제 데이터에서 계산 |
| 장소/예약 아이콘 | 오늘·지갑·분석 | 기존 소분류 Noto 컬러 자산, 같은 종류에 같은 아이콘 |
| 예약번호·주소 복사 | 오늘·지갑 상세·일정 | 동일 복사 도우미와 성공/실패 피드백 |
| 다음 장소/예약 요약 카드 | 오늘·지갑 | 제목·시각 우선, 긴 주소는 안정적으로 줄바꿈 |
| 상세/입력 창 | 예약·지출·저장 옵션 | `ui/dialog.js`, 기존 날짜·시간·select, 삭제 확인 재사용 |
| 연결 항목 행 | 예약↔일정/지출 | ID 기준 제목·상태·보기, 연결이 끊기면 복구 진입 |
| 진행/준비물 상태 행 | 오늘·도구 | 체크·숫자·라벨을 함께 표시, 색만으로 의미 전달하지 않음 |
| 일정 시간/이동 집계 | 요약·오늘·분석 | 같은 날짜·인접 항목·leg 기준을 공유 |

모바일 목표는 본문 14~16px, 보조 정보 12~13px, 제목 20~24px부터 실제 크기로 조정한다. 작은 연필 등 시각적 아이콘은 16~20px여도 누르는 영역은 약 44px를 확보한다. 전역 글꼴 크기를 일괄 변경하지 않고 해당 화면에 범위를 둔다.

모바일은 한 열, PC는 중앙 콘텐츠 폭 약 960px 안에서 두 패널을 사용한다. 오늘 화면은 대표 장소를 중심으로 이후 일정·바로가기를 보조 배치하고, 예약 지갑은 날짜순 목록을 유지한다. PC를 모바일 확대판이나 여러 예약 카드의 과도한 격자로 만들지 않는다.

## 6. 오늘의 여행

### 대표 장소와 날짜

- 여행지 시간대의 오늘을 사용한다. 여행 전은 첫날 미리보기, 종료 후는 마지막 날 기록. 직접 선택한 날짜는 자동으로 덮어쓰지 않는다.
- 현재 날짜·시각은 분 단위 및 화면 복귀 시 갱신한다. 현지 자정이 지나도 사용자가 고른 과거 날짜를 강제로 바꾸지 않는다.
- 대표 장소 선택은 유효한 개인 선택 위치 → 그 이후의 적절한 미완료/미건너뛴 항목 → 완료/빈 상태 순서다. 시간이 지났다는 이유로 완료시키지 않는다.
- 같은 이름의 장소가 여러 번 있어도 일정 ID로 구분한다. 삭제·날짜 이동된 선택은 잘못된 항목으로 대체하지 않고 현재 날짜의 유효한 위치로 재계산한다.

### 완료·건너뛰기·시작·되돌리기

| 동작 | 바꾸는 값 | 바꾸지 않는 값 |
| --- | --- | --- |
| 방문 완료 | 기존 공유 완료 상태, 내 다음 표시 위치 | 날짜·시간·일정 순서 |
| 건너뛰기 | 내 건너뛴 표시와 진행 위치 | 공유 완료 상태·일정 원본 |
| 여기부터 시작 | 내 표시 위치 | 이전 항목의 완료/건너뛰기 상태 |
| 되돌리기 | 방금 내 조작이 바꾼 필드와 표시 위치 | 이후 다른 사람이 변경한 필드 |

**권장 기본값:** 기존 방문 완료는 공유 상태로 유지한다. 새 건너뛰기·선택 위치는 계정/기기·여행·날짜별 개인 상태다. 동행에게 공유할 개인 진행 기능은 이번에 새로 만들지 않는다. 이 구분은 구현 전에 사용자에게 제시할 제품 결정이며, 현재 확정된 기능처럼 기록하지 않는다.

개인 상태는 기존 IndexedDB `meta` 저장소의 별도 키/접근자로 관리하는 방안을 우선한다. 여행 스냅샷의 임의 필드나 서버 progress 엔티티에 끼워 넣지 않는다. 비로그인은 기기별 별도 범위, 계정 전환은 계정별 범위를 사용한다. 저장된 일정 ID가 삭제되면 유효성을 재검사한다.

되돌리기는 전체 여행 스냅샷 복원 대신 해당 필드에 대한 역변경이다. 동일 항목을 다른 사용자가 변경했으면 최신 상태를 덮어쓰지 않는다. 기기 저장 실패 시 성공 토스트·다음 장소 확정을 하지 않으며 작성 상태를 유지한다.

### 연결 정보와 빠른 동작

- 대표 일정 ID가 바뀌면 예약번호·예약 상세·숙소·들어오는 이동을 함께 다시 계산한다.
- 예약이 없으면 예약번호/예매 행을 숨긴다. 오늘 숙소가 없으면 숙소로 버튼을 숨긴다. 남은 버튼 수에 따라 배치한다.
- 숙소 선택은 해당 날짜가 체크인 이상·체크아웃 미만인 예약/연결 일정 기준이다. 겹치는 숙소가 여러 개면 임의 하나를 확정하지 않고 선택하게 한다.
- 지도·길찾기는 현재 국내/해외 지도 도우미를 재사용한다. 주소/장소 복사에는 동일 도우미를 쓴다.
- 문구는 `이동 정보`. 같은 날짜의 실제 인접 일정 사이에 저장된 모든 이동 leg를 순서대로 표시한다. 첫 일정에는 들어오는 이동을 생성하지 않는다.
- 하루 완료·일정 없음·여행 전후·시간 미입력은 준비한 보조 상태를 사용한다.

### 빠른 지출

금액을 먼저 입력하고 분류·내용·여행 일자·결제일·통화·결제수단·결제자는 수정할 수 있게 한다. 상세 옵션은 접어 둔다. 기존 지출 폼의 검증/환산/결제자 선택을 간편 모드로 재사용하고 같은 DOM 폼을 두 곳에 복제하지 않는다.

선택 장소를 내용/분류의 초깃값으로 사용하되 GPS 위치로 표현하지 않는다. 여행 중 기본 여행 일자는 선택한 일정 일자, 실제 결제일은 별도 입력이다. 여행 전 미리보기에서 결제를 기록하면 사전구매와 실제 결제일을 확인할 수 있게 한다. 예약 연동의 선결제는 아래 규칙을 따른다.

저장 요청에 안정적인 항목/요청 ID와 중복 탭 방지를 적용한다. 성공한 기기 저장 이후에만 해당 일자 지출 합계·건수를 갱신하고 서버 전송 상태는 별도로 표시한다. 실패 시 금액과 선택값을 유지한다. 키보드가 올라와도 금액과 저장 버튼이 가려지지 않도록 visualViewport와 안전 영역을 처리한다.

## 7. 예약 지갑과 공통 상세/편집

### 목록과 당일 선별

- 상단 `오늘 필요한 예약`은 여행지 현지 이용일이 오늘인 **교통·입장권·식당 등 숙소 외 예약만** 포함한다.
- 숙박 중·당일 체크인 숙소도 상단에 넣지 않는다. 당일 예약이 없으면 한 줄 안내와 전체 예약 접근을 제공한다. 미래 예약이나 숙소로 빈자리를 채우지 않는다.
- 미래 예약은 날짜/시각순, 지난 예약은 기본 접힘. 숙소는 전체/숙소 필터의 일반 행으로 표시한다. 숙박 기간이 끝나지 않은 숙소를 체크인 날짜만 보고 지난 예약으로 분류하지 않는다.
- 검색·종류 필터·기존 정렬을 유지한다. 검색 중에는 검색 결과임을 명확히 하고 당일 예약이 없는 것과 결과가 없는 것을 구분한다.
- 목록에는 시각·이름·예약번호 복사·주요 열기 동작을 남긴다. 전체 주소·인원·좌석·메모는 상세에 둔다.
- 왕복 항공은 표시용 이용 회차를 가는 편/오는 편으로 분리해 귀국일에도 찾게 한다. 각 회차는 동일 원본 지출을 참조하며 예약/지출을 두 건 생성하지 않는다. 도착 시각과 복귀 출발 시각을 혼동하지 않는다.

### 상세와 입력

공통 상세 창에 교통/숙소/활동별 필드와 주요 동작만 바꾼다. 원본 티켓 URL과 예약 관리 URL을 구분한다. 티켓 URL이 없으면 `예약정보 보기`, 예약 URL이 없으면 외부 열기를 숨긴다. 기존에 저장된 첨부는 접근을 보존하지만 새 업로드를 주요 흐름에 넣지 않는다.

교통은 출발·도착 날짜/시각과 수단/구간, 숙소는 체크인·체크아웃 날짜 및 선택 시각, 활동은 이용 날짜/시각을 입력한다. 날짜·시간은 기존 공통 컴포넌트를 사용한다. 사용하지 않는 필드의 숨김/disabled/정리 규칙을 종류 변경 때 함께 처리한다.

숙소 예약에서 생성된 날짜별 일정은 기존 자동 추가 정책을 유지하고, 사용자가 수정한 날짜별 시작·종료·장소·메모를 불필요하게 덮어쓰지 않는다. 기존 일정 연결은 선택한 ID에 연결만 하고, 새 일정 추가와 구분한다. 이미 연결된 항목은 보기 동작으로 전환한다.

### 원본의 소유권

| 표시 예약 | 원본 | 수정 경로 |
| --- | --- | --- |
| `manual:<id>` | 직접 등록 예약 | 공통 예약 편집 → 도메인 명령 |
| `entry:<id>` | 항공/숙소 사전구매 지출 | 기존 원본 지출 예약 필드를 수정, 수동 예약 복제 금지 |
| `plan:<id>` | 일정의 바우처 | 연결된 일정의 바우처/메모 수정 |

지출 연결로 동일 원본 예약이 중복 표시될 때는 **명시적 연결 ID만** 기준으로 조회 단계에서 통합한다. 이름·금액·날짜가 비슷하다는 이유로 합치지 않는다. 기존 `linkedReservationId`와 원본 ID는 보존하고 필요한 조회 별칭을 둔다.

## 8. 예약 금액·지출 연결

예약 편집 하단의 `금액 · 지출 연동`은 기본 접힘이다. 지갑 메인에 결제 요약 패널을 만들지 않는다.

### 이번 버전의 권장 범위

실결제 1건 생성 또는 기존 지출 1건 연결을 우선한다. 예약금/잔금 분할 화면, 결제 이력, 미결제 잔액 대시보드는 이번 간결한 목업 범위에서 보류한다. 오래된 동작 제안의 다회 결제 설계를 새 필수 화면으로 되살리지 않는다. 추후 확장 가능하도록 연결을 ID 기준의 별도 도메인 동작으로 둔다.

| 선택 | 저장 동작 | 지출 합계 |
| --- | --- | --- |
| 금액만 메모 / 연동 끔 | 예약 금액 정보만 저장 | 증가 없음 |
| 새 지출 기록 | 실제 결제 정보로 지출 한 건과 연결을 함께 저장 | 실제 결제만 반영 |
| 기존 지출 연결 | 사용자가 고른 지출 ID 재사용 | 추가 생성 없음 |
| 연결 해제 | 관계만 제거 | 기존 지출 유지 |
| 예약 취소/삭제 | 예약 상태/연결 처리 | 지출 자동 삭제·환불 없음 |

예약 총액/예정 금액과 실제 결제는 구분한다. 선결제는 여행 일자 `사전구매`와 실제 결제일을 함께 저장한다. 이용일을 결제일로 덮어쓰지 않는다. 외화 원금·통화·환율·환율 기준 단위를 보존하고 기존 공통 환산 함수를 사용한다.

### 갱신·중복·충돌

- 실제 결제 정보 변경은 연결된 동일 지출 ID를 갱신한다. 예약 이름·이용일·총액만 수정하면 지출 금액/결제일을 덮어쓰지 않는다.
- 기존 지출 연결 시 먼저 내용을 보여주며, 해당 지출이 일정 교통비 등 다른 원본의 자동 연동 대상이면 그 소유 규칙을 확인한다. 새 예약에서 무단으로 지출을 지배하지 않는다.
- 연결된 지출을 지출 화면에서 수정하면 예약 화면은 최신 값을 조회한다. 삭제되면 없는 금액을 캐시로 표시하지 않고 연결 끊김을 보여준다.
- 예약과 새 지출은 한 도메인 변경/한 기기 저장으로 처리한다. 저장 중복 탭·같은 요청 재시도에서 원본 ID와 지출 ID를 재사용한다.
- 기존 repository는 여러 엔티티 패치와 기기 충돌 처리를 제공한다. 이를 재사용하고 서버 operation 한 건의 충돌/재시도에서도 한쪽만 남지 않는지 격리 검증한다. 운영 서버의 원자성까지 이 계획만으로 보장했다고 보고하지 않는다.

### 저장·공유 계약

새 예약 메타데이터, 링크, 지출 참조를 정규화·허용 필드·기본값·검증·저장/복원·CLI 스키마에 함께 반영한다. 새 필드가 UI에만 존재하다 사라지는 상태를 막는다.

실제 결제 금액은 지출 원본을 기준으로 표시하고 중복 저장을 최소화한다. 일정은 공유하지만 지출은 비공개인 경우 예약 엔티티를 통해 금액·결제자·결제일이 우회 공유되지 않게 한다. 예약 총액 같은 새 금액 메타데이터도 같은 지출 공개 정책을 적용하거나 개인 영역에 보관한다. 보기 전용 사용자는 조회·복사는 가능하고 공유 데이터 수정은 제한한다.

새 서버 테이블·스토리지·파일 업로드를 기본 전제로 삼지 않는다. 기존 엔티티/동기화 계약으로 가능한지 먼저 확인한다. 서버 검증/정책 변경이 필요하면 구체적인 변경과 로컬 검증을 따로 준비하고 배포 요청 때 해당 범위를 명시한다.

## 9. 여행 도구

준비물 요약 → 준비물 전체 편집 → 오프라인 저장 → 캘린더 파일 → 시간대 순서로 구성한다. 큰 포켓노트 표지는 내려놓고 필요한 항목에 공간을 쓴다.

- 준비물 메인은 완료 수/전체 수, 남은 항목, 추가/전체 편집을 제공한다.
- 전체 목록은 전체/남은 항목 필터, 즉시 체크, 인라인 이름 수정·추가를 제공한다. 삭제/초기화는 기존 확인창을 사용한다.
- 기존 이동 기능을 보존한다. 순서 핸들을 채택하면 기존 공통 sortable을 사용하며 모바일 키보드 조작 대안도 둔다. 정렬만을 위한 새 라이브러리는 추가하지 않는다.
- 도구 내부 체크와 전체 편집은 같은 원본·명령을 사용한다. 빈 목록/모두 완료/저장 실패를 구분한다.
- 오프라인 정보는 저장할 일정·예약정보·기록된 경비의 범위와 미리보기를 일치시킨다. 현재 `references` 옵션은 번호/메모만 숨기고 예약 기본 행은 남기므로 새 화면의 범위 선택을 그대로 연결하면 안 된다. UI에 맞는 예약 포함 옵션을 추가하면서 기존 CLI/모델 호출의 기본 동작은 보존한다.
- 예약번호를 포함한 파일은 개인 기기에 보관한다는 짧은 기존 안내를 유지한다. 파일 용량은 실제 생성한 값만 표시한다.
- ICS는 파일을 생성해 사용자가 캘린더로 가져오는 기능이다. 지원이 확인되지 않은 파일 저장 완료를 기기에 확정 저장된 것처럼 알리지 않는다.
- 시간대 변경은 날짜 기본 선택·오늘 예약·캘린더 출력에 함께 반영한다. 임의로 일정 시각을 변환해 덮어쓰지 않는다.

## 10. 일정 분석

### 정보 구조

전체/날짜 선택 → 계획 일정 수·입력된 체류·기록된 구간 이동 → 날짜별 비교 → 장소별 목록 → 미입력 진입 순서다. 선택 날짜·정렬·스크롤은 편집 후 복귀 때 유지한다. 로컬 여행 전환 시 다른 여행의 필터·목록이 남지 않게 한다.

모바일 날짜별 비교는 공통 0점의 수평 누적 막대, PC는 그 비교와 순위를 나란히 배치한다. 구간 값과 단위를 직접 표시하고 색 외에 범례·이름을 둔다. 막대가 짧아 글씨가 들어가지 않으면 값을 바깥에 표시한다. hover가 없어도 읽고 조작할 수 있어야 한다.

### 제안 계산 기준 — 구현 전 고정할 규칙

| 값 | 권장 규칙 |
| --- | --- |
| 계획 일정 수 | 선택 기간의 모든 일정, 숙소·교통 포함 |
| 체류 합계/순위 | 유효한 시작·종료를 입력한 장소 일정. 숙소 제외 |
| 교통 테마 | 교통 예약 자체의 시간은 체류로 오해되지 않게 별도 처리. 권장안은 장소 체류에서 제외하고 상세에는 원래 시각 유지 |
| 구간 이동 | 같은 날짜의 실제 인접 일정 사이에 저장된 모든 leg 합. 첫 일정의 고립된 incoming 값 제외 |
| 교통 예약 시간 | 구간 이동 leg와 중복해 더하지 않음. 이번 막대는 `구간 이동`임을 명시 |
| 미입력 | 유효 시간 없음/일부 leg 누락을 별도 건수로 표시. 0분과 구별 |
| 겹친 일정 | 각 입력 기간의 합, 하루 실제 활동 시간이나 여유시간으로 표현하지 않음 |
| 정렬 | 일정순/긴순/짧은순, 미입력 마지막, 동률은 기존 일정 순서 유지 |
| 자정 넘김 | 공통 날짜/도착일 규칙으로 계산. 모든 음수 차이를 무조건 다음 날로 보정하지 않음 |

현재 리포트는 숙소 외 교통 테마도 체류 목록에 넣고 전체 항목의 이동을 합한다. 위 교통 테마/인접 구간 처리는 개선 제안이므로 수치 의미 변경을 테스트와 문구에 명시한다. 목업 수치를 유지하려고 누락 데이터를 가공하지 않는다.

미입력 목록은 장소 시간과 이동 leg를 나눠 보여준다. 이동 입력은 대상 일정 ID·이전 일정 ID·leg 위치를 가지고 기존 수동 이동 편집기를 연다. 입력 직전에도 인접 관계를 다시 확인하고 변경됐으면 현재 구간을 안내한다. 별도 일정 점검이나 자동 조정 UI로 연결하지 않는다.

## 11. 코드 작업 경계

기존 브라우저 전역/등록 방식과 정적 앱 구성을 유지한다. React 전환이나 전역 CSS 재작성은 이 범위에 포함하지 않는다. 아래 새 모듈 이름은 역할을 설명하는 제안이며 기존 의존성 순서를 확인해 확정한다.

| 역할 | 기존 수정 지점 | 분리/추가 제안 |
| --- | --- | --- |
| 진입·탐색 | `navigation/trip-navigation.js`, `features/redesign/design-workspace.js` | 점검 제거, analysis 호환 진입, 복귀 문맥 |
| companion 조정 | `features/travel-companion/workspace.js` | 셸/이벤트 연결만 남기고 화면별 view로 분리 |
| 오늘/예약 조회 | `features/travel-companion/model.js` | 날짜/예약 회차/연결 조회 selector, 개인 진행 모델 |
| 예약 화면 | 같은 workspace | wallet view/detail/editor, 공통 상세 계약 |
| 지출 연결 | `domain/commands.js`, `features/expenses/*` | 예약-지출 연결 도메인 도우미, 기존 expense 간편 모드 |
| 준비물 | `features/packing/packing-list.js`, `packing-workspace.js` | 원본 명령 공용화, 행/필터 재사용 |
| 시간 집계 | `features/reports/report-workspace.js`, `features/itinerary/itinerary-summary.js` | 렌더링과 분리한 공유 분석 모델 |
| 개인/공유 저장 | `persistence/state-storage.js`, `sync/repository.js`, `sync/model.js`, backup/history | 개인 meta 접근자, 새 필드 정규화/공유 필터/복원 |
| 공통 UI | `ui/dialog.js`, 날짜/시간/select/confirmation, 지도·복사 도우미 | 기존 API 재사용, 필요한 최소 옵션만 확장 |
| 스타일 | `travel-companion.css`, `companion-passport.css`, `reservation-wallet.css`, 리포트 스타일 | 기존 소유 스타일 정리·범위 제한, 무조건 덧붙이는 override 방지 |
| 로드/배포 자산 | `app.js`, `Travel.html`, `scripts/app-assets.js` | 신규 런타임 모듈만 등록, 목업 이미지는 캐시/배포 제외 |

서버 공용 모델은 `prepare:sync`로 생성하므로 생성 사본만 직접 고치지 않는다. 새 공유 데이터 계약은 CLI/file/cloud/백업의 왕복까지 같은 필드로 유지한다. 개인 진행 위치는 공유 백업에 넣지 않는 것을 기본값으로 한다.

| 단계 | 작업 묶음 | 완료 조건 | 선행 |

## 13. 검증 계획과 완료 기준

자세한 사례는 [acceptance-checklist.md](acceptance-checklist.md)에 둔다. 실제 구현 때 다음을 변경 범위에 맞춰 실행한다.

- 소스/산출물: `node bin/triplog.js dev test --suite source --json`, `node bin/triplog.js dev artifacts --json`.
- 모델/도메인: 기존 companion·지출·순서·환율 회귀에 신규 계약 사례 추가, 공유 명령 변경 시 CLI 검사.
- 저장/동기화: 기존 sync·backup 회귀에 필드 왕복, 권한, 비공개 금액, 다중 엔티티 충돌, 재시도 추가. 서버 원자성은 격리 환경에서 확인.
- 브라우저: 기존 companion-passport, wallet-passbook, reservation-expense-editor, transport/stay/time, itinerary-summary, travel-costs, report 관련 suite를 새 UI에 맞게 갱신하고 실제 상호작용을 검증.
- 통합: 공통 계약을 바꾸므로 최종적으로 전체 관련 검사와 build를 실행하고 생성된 Travel.html/sw.js/공유 자산 변경을 확인.

화면은 **320 / 390 / 768 / 1440px**와 모바일 전환점 양쪽, 긴 여행명/주소/예약번호에서 비교한다. iOS Safari·Android Chrome은 실제 또는 사용 가능한 모바일 환경에서 키보드/다운로드/뒤로 가기를 확인한다. 데스크톱 브라우저의 모바일 에뮬레이션을 실제 기기 검증으로 보고하지 않는다.

큰 UI 재구성에는 정상 데이터 외에 빈 여행·모두 완료·누락 시간·다중 교통·왕복·중복 장소·비공개 지출·보기 전용·저장 실패·여행/계정 전환 fixture를 사용한다. 사용자 브라우저 저장소나 운영 여행은 검증 원본으로 수정하지 않는다.

최종 근거는 `artifacts/qa/<구현일>-companion-redesign/`, 작업 로그/전체 캡처는 artifact helper를 통해 `artifacts/tmp/`에 둔다. 목업과 동일 조건으로 실제 폰트·행 높이·내용 밀도·노출 항목 수를 비교한다. 단순히 overflow가 없다는 이유로 시각 검증을 통과시키지 않는다.

**구현 완료는 네 화면이 연결되고, 저장/재열기/복원 후 값이 유지되며, 예약과 지출이 중복되지 않고, 누락·오류 상태와 실제 모바일 동작까지 확인된 상태다.** 로컬 완료, Git 푸시, 운영 자동 배포는 구분한다.

## 14. 구현 전 제안 기본값

다음은 막연한 미정 사항을 줄이기 위한 권장안이며, 이 계획을 작성했다는 이유로 사용자 승인을 받았다고 간주하지 않는다.

| 결정 | 제안 기본값 | 이유 |
| --- | --- | --- |
| 진행 공유 | 기존 완료는 공유, 건너뛰기/여기부터 시작은 개인 | 기존 의미 보존, 서로의 화면 위치 간섭 방지 |
| 결제 범위 | 실제 결제 1건 또는 기존 지출 연결, 분할 UI 보류 | 예약 사용성을 중심에 둔 최신 요구 유지 |
| 계산 의미 | 숙소 체류 제외, 교통은 장소 체류와 구간 이동에서 중복 계산 방지 | 표시 값의 의미 명확화 |
| 예약 상단 날짜 | 여행지의 실제 오늘, 숙소 제외 | 여행 전후에도 다른 예약을 오늘이라고 오인하지 않음 |
| PC | 기존 중앙 폭 + 역할별 2패널, 지갑은 날짜순 목록 | 모바일과 같은 정보/동작 유지 |
| 새 외부 의존성 | 기존 아이콘·차트 표현·지도·정렬·입력 컴포넌트 우선 | 디자인/저장 계약 유지, 불필요한 의존성 방지 |

오늘의 여행 keep 결정은 유지한다. 나머지 최신 목업은 위 기본값과 함께 한 번에 검토할 수 있는 구현 기준으로 묶는다. 추가 이미지가 꼭 필요한 상태는 현재 없다. 미세한 간격·폰트·키보드 동작은 구현 중 실제 화면에서 비교하며 다듬는다.
