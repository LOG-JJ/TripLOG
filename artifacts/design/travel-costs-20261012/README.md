# 앱 기본 기능: 여행 예산 → 누적 여행 경비

사용자 요청에 따라 개요 카드부터 앱의 계획 예산 기능을 누적 지출 표시로 전환했다. 일정 4번·지출 1번으로 선택한 PDF 구성은 유지한다.

## 표시와 계산

- 개요와 지출 화면은 **여행 경비 / 누적 금액 / 기록한 지출 건수 / 1인 평균**을 표시한다. 예시 14건의 합계는 486,000원이며 2명 평균은 243,000원이다.
- 예산 입력·수정, 사용률 막대, 남은 예산, 초과 경고와 하루 예산 배분을 제거했다. 개요 카드의 `지출 기록 보기`는 실제 지출 목록으로 이동한다.
- 오늘 일정에는 선택한 날짜에 기록한 금액과 건수를 표시한다. 상세에는 해당 날짜·전체 누적·사전구매 금액을 표시한다.
- 포켓노트의 `경비 포함`은 저장 당시 누적 지출과 건수를 담는다.
- 모든 금액은 저장된 `entries[].amount`의 합계다. 사전구매·날짜 미정·기간 밖 기록을 포함하며 환불은 음수로 차감한다. 해외 지출은 이미 저장한 원화 환산액을 사용한다.
- 1인 평균은 현재 여행 멤버 수로 나누어 원 단위 반올림한다. 실제 송금액이나 개별 분담액을 뜻하지 않으며 정산 계산은 기존 기능을 따른다.
- 지출 추가·수정·삭제와 멤버 변경에 따라 다시 계산한다. 지출 검색·분류·기간 탭은 목록만 바꾸며 전체 누적 금액은 유지한다.
- 기존 `totalBudget`은 백업·동기화 호환성을 위해 보존한다. 현재 화면의 입력과 계산에는 사용하지 않는다. 데이터베이스 구조를 변경하지 않았다.

## 검증

- `node tests/travel-costs-regression.js`: 사전구매·환불·외화 환산액·날짜 미정·기간 밖 기록·추가/수정/삭제·인원 평균·과거 예산 값과의 독립성 통과.
- `node tests/travel-costs-browser-regression.js`: 개요/지출/리포트/오늘 일정, 추가/수정/명시적 삭제, 재접속 보존, 여행별 분리, 검색·필터·빈 데이터와 320/390/759/760/1024/1440px 넘침 검사 통과.
- 기존 지출 입력 및 여행 동행 테스트는 누적 경비의 새 동작을 검증하도록 갱신했다. 삭제된 예산 편집 전용 테스트는 경비 테스트로 교체했다.
- 실제 여행 데이터를 쓰지 않는 격리 서버·가상 계정·별도 브라우저에서 수행했다. 인앱 브라우저에서도 개요의 486,000원·14건·1인 평균과 지출 화면 이동을 직접 확인했다.
- 전체 검사·빌드 결과는 프로젝트 루트 `../design-qa.md`의 최신 항목에 기록한다.
- 최종 `npm test`, 전체 `npm run test:browser`, `npm run test:print`, `npm run build`, `git diff --check` 모두 통과했다. 로컬 빌드는 `4d617d35402242cdd073`이다.
