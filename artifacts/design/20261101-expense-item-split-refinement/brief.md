# 결제자 아래 분담 설정 — 선택 1안 수정 목업

2026-11-01 · Asia/Seoul

사용자 요청: ‘지금 디자인톤에서 결제자 아래에 추가하는 거라서 분담 설정만 있으면 될 듯’, ‘1번이 제일 좋은 듯, 1번을 개선’. 기존 전체 지출 수정창을 다시 디자인하지 않고 결제자 입력 바로 아래에 삽입할 분담 설정 영역만 제작했다.

표시된 두 영역은 같은 컴포넌트의 금액 입력·비율 입력 상태다. 화면에 둘을 동시에 배치하는 제안이 아니다.

- 기존 필드와 같은 흰 바탕, 남색 입력 테두리, 9px 모서리, 노란 선택 버튼.
- 390px 화면의 좌우 18px 안쪽, 354px 폭을 기준으로 작성.
- 균등 / 금액 / 비율 선택. 금액 입력 시 비율이 계산되고, 비율 입력 시 금액이 계산되는 구조.
- 가상 동행 JJ/JH/민지, 60,000/36,000/24,000원 = 50/30/20%, 합계 120,000원.
- 작은 이니셜 아바타, 사람 이름, 입력칸, 자동 계산값, 간단한 합계 확인만 포함.
- 별도 분담 적용/저장 버튼을 추가하지 않고 기존 ‘변경 내용 저장’에 연결할 방향. 입력 중 변경은 지출 편집 초안으로 다룬다.
- 기존 결제자·금액·분류·날짜·메모 등의 필드를 변경하는 목업이 아니다.

사용자가 특정 1번 목업의 수정을 명시해 선택 원본 한 장만 입력한 I2I 1회로 제작했다. 자동으로 생성 결과를 반복 입력한 연쇄 편집은 하지 않았다. [이미지](allocation-component.png), [최종 프롬프트](prompt.txt), 정확한 입력/호출 원본 경로·SHA256·크기를 담은 [생성 기록](generation.json)을 보존한다. 출력은 호출이 반환한 정확한 경로에서 복사하고 SHA256을 대조했다. 기존 파일은 덮어쓰지 않았다.

이번 단계는 이미지 목업 제작만 수행했다. 앱 소스·운영 여행 데이터·배포에는 변경하지 않았다. 선택 후 구현 전에 합계 미충족, 총액 변경, 원 단위 반올림, 외화/환불 처리와 취소·저장 계약을 함께 정리한다.

후속 구현(2026-11-01): 사용자의 ‘이걸로 구현해줘’ 요청으로 기존 지출 편집창에 연결했다. 실제 모바일 비교와 저장·정산 검증은 [구현 QA](../../qa/20261101-expense-allocation/design-qa.md)에 보존한다. 생성 원본과 프롬프트는 변경하지 않았다.
