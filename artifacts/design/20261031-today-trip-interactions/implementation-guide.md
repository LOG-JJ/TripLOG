## 진행 상태 계약

- 방문 완료는 명시적인 사용자 조작으로만 처리한다. 시간이 지났거나 길찾기를 열었다는 이유로 완료하지 않는다.
- 완료·건너뛰기는 서로 다른 상태이며 다음 장소로 이동하더라도 원래 일정의 날짜·시각·순서를 바꾸지 않는다.
- 되돌리기는 방금 한 진행 조작과 표시할 장소를 복구한다. 여행 계획 자체를 재정렬하거나 시간을 조정하는 기능과 섞지 않는다.
- ‘여기부터 시작’은 목록에서 대상을 명시적으로 선택하게 한다. 이전 미확인 장소를 자동 완료·삭제·건너뛰기 처리하지 않는다.
- 사용자가 고른 진행 위치를 우선한다. 다음으로 넘어갈 때 선택 위치 이후의 적절한 미완료 일정을 확인하며, 무조건 첫 미완료 장소로 돌아가지 않는다.
- 개인 진행 표시와 공유 일정의 저장 범위를 무심코 같은 상태로 취급하지 않는다. 구현 시 현재 협업 모델의 소유 범위를 확인한다.

## 연관 정보 갱신

- 대표 장소가 바뀌면 예약번호·예매 내역·이동 정보도 새 선택 항목의 ID 기준으로 다시 계산한다. 이전 장소의 티켓을 새 장소 아래에 남기지 않는다.
- 연결된 예약이 없으면 예약번호 바로가기와 예매 내역을 함께 숨기고 남은 바로가기를 재배치한다.
- 오늘 묵을 숙소가 없으면 ‘숙소로’를 숨긴다. 예약도 숙소도 없으면 지출 바로가기만 남기는 등 남은 개수에 맞춰 정렬한다.
- ‘이동한 기록’ 대신 ‘이동 정보’를 사용한다. 저장된 계획 구간임을 유지하고 실제 이동·위치를 추적한 것으로 표현하지 않는다.
- 저장된 다중 교통 구간은 모두 순서대로 표시한다. 미입력 시간을 임의 추정값으로 채우지 않는다. 같은 날짜의 인접 장소가 없는 첫 일정에서는 들어오는 이동 구간을 만들지 않는다.

## 빠른 지출 계약

- 날짜·선택한 장소·분류를 미리 채우되 모두 수정 가능하다. 선택한 장소는 GPS로 확인한 실제 위치를 뜻하지 않는다.
- 통화·카드/현금·결제자는 기존 여행 설정과 최근 입력을 재사용하고 선택적으로 수정한다. 금액 입력을 우선하고 나머지 입력은 접어 둔다.
- 숫자 키보드가 올라왔을 때 금액과 저장 동작이 보이도록 실제 visualViewport·안전 영역을 고려한다. 그림에 나온 키보드를 앱 내부 키패드로 구현하지 않는다.
- 실제 저장 성공 후에만 지출 건수·합계와 완료 피드백을 바꾼다. 실패하면 작성값을 유지하고 동일 화면에서 다시 저장하게 한다. 중복 탭으로 여러 건을 생성하지 않는다.
- 지출 기록은 방문 완료나 일정 시각을 변경하지 않는다.
- 목업의 예시 환율은 100엔=950원이며 2,700엔=25,650원이다. 예시 합계는 86,000원·4건에서 111,650원·5건으로 바뀐다. 실제 앱에서는 기존 원화 환산·결제일·지출 합계 계약을 사용한다.

## 날짜·누락 정보

- 여행지 현지 날짜·시각으로 기본 날짜를 고른다. 여행 전은 첫날 미리보기, 여행 후는 마지막 날 기록을 기본으로 한다.
- 오늘 일정이 없으면 짧은 안내와 일정 추가를 제공하고 다른 날짜 일정으로 대체하지 않는다.
- 모든 일정을 마친 상태는 다음 장소 대신 완료 목록·이날 경비를 간결하게 보여준다.
- 이미지 속 Day 번호·날짜·주소·예약번호·통화·금액·완료 수는 예시다. 실제 구현에서는 여행과 선택 날짜에서 계산하며, 생성 이미지 텍스트를 데이터 규칙으로 사용하지 않는다.

## 구현 후 확인할 범위
