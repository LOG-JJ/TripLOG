# 해외 목적지 500곳 확장과 국가별 누락 보완 계획

**실행 완료:** 해외 540곳·국내 포함 635곳 연결, 신규 480장 생성·원본 해시 확인 및 로컬 검증·빌드 완료. 상세 결과는 [제작 기록](README.md)과 [검증 보고서](../../qa/20261017-world-city-expansion-500/README.md)를 참고한다.

2026-10-17 사용자 요청에 따라 계획 작성 후 별도 승인 질문 없이 제작·구현·검증까지 수행한다. 기본 확장은 **기존 해외 300곳 + 신규 주요 관광도시 200곳 = 500곳**이며, 이어서 **국가별 최소 한 도시/정착지**가 없는 곳을 추가한다. 따라서 최종 해외 수는 500곳을 넘을 수 있다.

**합본 확정:** 1차 500곳에서 남는 도시·정착지 공백은 40개 국가·지역이다. 이 40곳을 추가해 최종 해외 **540곳**, 국내 포함 **635곳**, 신규 그림 **240쌍·480장**, 공통 테마 포함 활성 이미지 **1,290개**로 확정했다. 최종 계획의 필수 해외 242개 코드 누락과 도시 ID·국가별 정규화 별칭 충돌은 모두 0건이다. 정확한 항목은 `expansion-plan.json`을 따른다.

## 현재 기준

기존 카탈로그는 국내 95곳·해외 300곳이다. 활성 이미지 810개와 카탈로그를 `baseline-inventory.json`에 해시와 함께 저장했다. 해외 300곳은 직접 국가코드 기준 91개 국가·지역을 커버하지만, 도시·소도시 및 명시한 도시권 예외만 세면 86개다. 섬 전체의 그림을 한 도시의 그림으로 세지 않는다.

## 국가와 도시 범위

UN 회원 193개국과 옵서버 2개를 기본 국가 집합으로 삼고, 이미 국내 95곳이 있는 대한민국을 제외한 해외 194개국을 모두 충족시킨다. 앱이 별도로 선택하도록 제공하는 대만·코소보 2개 코드와 유인 별도지역 46개도 같은 방식으로 확인한다. 해외 필수 코드는 총 242개다. 국가·지역 구분은 `country-inventory.json`과 `country-coverage-plan.md`에 근거와 예외를 기록한다.

- 기본 충족 항목은 실제 `city` 또는 `town`이다. 국가 코드가 같더라도 섬·광역 지역만 있는 것은 도시 충족으로 세지 않는다.
- 싱가포르·홍콩·마카오는 기존 카탈로그가 `region`으로 표현한 실제 도시권이므로 목적지 ID를 한정하여 인정한다.
- 나우루는 법정 도시를 꾸며내지 않고 정부 중심지 야렌을 실제 정착권역으로 구분한다.
- 남극(AQ), 부베섬(BV), 사우스조지아·사우스샌드위치(GS), 허드·맥도널드(HM), 영국령 인도양 지역(IO), 프랑스령 남방 지역(TF), 미국령 군소 제도(UM)는 일반 관광 도시·정착지 요건에서 제외하고 기존 공통 그림 동작을 유지한다.
- 팔레스타인은 기존 예루살렘 보조 코드만으로 충족시키지 않고 PS를 첫 국가 코드로 가진 별도 실제 도시를 포함한다.

## 단계

1. **기본 500곳:** 기존 300곳을 보존하고 유럽·아메리카 100곳, 아시아·아프리카·오세아니아 100곳을 추가한다. 미등록 국가의 대표 관광도시를 먼저 포함하고 남는 수량을 기존 국가의 주요 관광도시로 채운다. 인기도 순위나 여행 가능성 순위가 아닌 편집 목록이다.
2. **국가별 추가 보완:** 500곳을 확정한 뒤 242개 필수 코드와 다시 비교한다. 누락된 국가·지역에는 실제 도시·소도시·정착지 한 곳씩 추가한다. 괌·사이판·타히티 등 기존 섬 전체 그림은 유지하고 도시 그림을 별도로 연결한다.
3. **이미지 제작:** 모든 신규 목적지마다 PC와 모바일을 독립 T2I로 생성한다. 기존 그림·목업은 이미지 입력으로 제공하지 않는다. 최종 프롬프트·정확한 반환 원본 경로·시각·SHA256을 기록하고 원본을 그대로 보존한다.
4. **앱 연결:** 새 자산은 `src/assets/trip-scenes/cities/v6/`를 사용한다. 목적지 카탈로그, 국가명/도시명 별칭과 검증 fixture를 함께 갱신한다. 기존 국내 95곳·해외 300곳의 이미지 경로와 저장 데이터를 유지한다.
5. **검증과 기록:** 원본·출력 해시, 규격·투명도, 242개 국가/지역의 도시 충족, 동명 도시와 국가명 입력을 검사한다. 전체 해외 목적지를 320·390·599·1440px에서 검사하고 전환점 양쪽·613px·PC·긴 제목을 추가 확인한다. 이미지 실패·오프라인·48개 캐시 한도, 전체 테스트·소스 검사·빌드를 완료한다.

## 그림 기준

현재 손그림 외곽선과 밝은 파스텔 면색, 간결한 여행지 실루엣을 유지한다. 한 장에 지역을 식별하는 주요 소재 하나와 보조 요소 한두 개를 사용한다. 실제 관광청·정부·유산기관 자료로 도시와 소재 관계를 확인하고, 임의의 유명 건축물을 다른 도시로 옮기지 않는다.

PC는 **800×480(5:3)**, 모바일은 **480×600(4:5)** 투명 WebP다. 모바일은 별도 세로 구도로 제작한다. 주요 건축물·탑의 식별 가능한 전체 윤곽을 프레임 안에 넣고, 오른쪽과 아래의 실제 채색 픽셀이 카드 테두리에 닿도록 확인한다. 정보 왼쪽·그림 오른쪽 배치는 유지한다.

## 검증·보관

원본과 최종 프롬프트는 이 디자인 폴더에, 완료 보고서와 대표 캡처는 `artifacts/qa/20261017-world-city-expansion-500/`에, 작업 스크립트·전체 캡처·로그는 Git에서 제외하는 `artifacts/tmp/20261017-world-city-expansion-500/`에 보관한다. 생성 도구가 반환한 정확한 원본을 지정하여 저장하고 최신 파일 검색으로 선택하지 않는다.

검증 명령은 현재 package.json과 기존 Playwright/Edge 회귀 스크립트를 사용한다. Browser 플러그인 및 browser 스킬이 없는 환경이므로 저장소의 Playwright 경로를 따른다. 검증 흐름은 격리 여행 개요 → 국가·도시가 다른 여행 선택 → 해당 전용 그림·반응형 구도 확인이다. 사용자의 운영 여행 데이터에는 접근하거나 쓰지 않는다.

`npm test`, `npm run test:source`, `npm run artifacts:check`, 목적지·헤더·이미지 캐시 브라우저 검사, `npm run build`를 수행한다. 커밋·푸시·운영 배포는 별도 배포 요청이 없으므로 이 계획의 실행 범위에 포함하지 않는다.
