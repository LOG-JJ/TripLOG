# 지출 원장과 연결하는 경비 정산 — 개편 목업

2026-11-01 · Asia/Seoul · 사용자 검토 대기

사용자는 기존 정산의 연결성과 디자인을 지적하며, 지출의 분담 설정과 연결하고 상단을 기존 지출 톤으로 개선하며 지출로 돌아가는 버튼을 추가하는 목업을 요청했다. 이번 작업은 이미지 목업과 구현 방향 기록만 수행했다. 앱 소스·여행 데이터·운영 배포를 변경하지 않았다.

## 목업

1. [정산 요약 — 모바일·PC](settlement-overview.png): 기존 지출의 여행 정보·경비 요약, 정산 요약/항목별 분담 탭, 송금 안내와 멤버별 결제·분담·차액.
2. [항목별 분담 → 기존 지출 수정](settlement-item-flow.png): 원래 지출 목록의 결제자·분담액을 확인하고 기존 지출 편집기의 균등/금액/비율 컴포넌트로 수정하는 흐름.

두 이미지는 대안이 아니라 하나의 개편안의 연결 화면이다. 기본은 이미지 입력 없는 T2I 2회이며 이전 목업을 반복 입력하지 않았다. [요약 화면 최종 프롬프트](overview-prompt.txt), [항목 수정 흐름 최종 프롬프트](flow-prompt.txt), [호출 원본 경로·시각·SHA256·예시 계산](generation.json)을 보존했다. 각각 정확한 도구 반환 원본과 저장본의 SHA256을 대조했다. 기존 파일을 덮어쓰지 않았다.

## 제안하는 동작

- 현재 여행의 지출을 기준으로 정산한다. 지출의 금액·결제자와 `settlement.itemSplits[current:<entryId>]`에 저장한 분담액을 함께 사용한다.
- 상단은 기존 지출 화면의 공통 경비 요약 컴포넌트를 재사용한다. 전체 합계·1인 평균·건수를 표시하고, 실제 개인 분담액과 받을/보낼 돈은 멤버 영역에서 구분한다.
- 항목별 분담은 같은 지출 레코드와 같은 저장된 분담의 읽기 화면이다. 균등과 직접 분담을 표시하고 연필로 기존 지출 편집기를 연다. 별도의 복사된 분담 데이터나 새로운 계산기를 만들지 않는 방향이다.
- 기존 지출 편집의 균등/금액/비율을 그대로 재사용한다. 기존 변경 내용 저장 한 번으로 저장하고 정산 요약·항목 목록·송금 안내를 갱신한 뒤 정산의 기존 탭과 읽던 위치로 복귀한다.
- 상단의 왼쪽 화살표 `지출로` 버튼은 현재 여행의 지출 내역으로 돌아간다. 이 기능은 명시적인 버튼으로 항상 찾을 수 있게 한다.
- 공통 로고·여행 정보·하단 탐색·실제 지출 편집 폼은 기존 프로젝트 컴포넌트를 사용한다. 하단 메뉴는 개요/일정/여행/지출/리포트이고 정산에서는 지출을 활성 표시한다. 생성 이미지의 주변 장식을 공통 탐색 구조 변경으로 확대하지 않는다.

## 코드에서 확인한 기존 문제

- 기존 정산 계산도 항목별 `itemSplits`와 `payerKey`를 읽고 있다. 데이터가 전혀 연결되지 않은 구조는 아니지만, 새 지출 분담 편집기와 예전 항목별 분담 편집기가 동시에 존재한다.
- 예전 편집기의 직접 분담 전환에는 `seedEntryCustomShares(..., {force:true})`로 균등값을 다시 넣는 경로가 있다. 저장된 직접 분담을 의도치 않게 바꾸는 위험이 있어 기존 지출 편집기와 저장 계약으로 일원화할 필요가 있다.
- 기존 `getSettlementEntriesForSource()`는 음수 지출을 0으로 잘라 계산하고, `buildSettlementModel()`은 원장 밖 `individualSpent`를 더한다. 지출 화면의 합계와 정산 상단이 다른 금액을 보일 수 있다.
- 기존 정산 상단의 평균 부담액은 실제 개인별 분담액과 구분이 약하다. 새 구조는 1인 평균을 공통 경비 카드에 두고 개인별 실제 분담액·차액을 별도로 표시한다.

구현 시 지출 화면의 환불 포함 합계와 정산의 결제액·분담액·차액을 같은 계약으로 맞춰야 한다. 기존 원장 밖 추가 지출 값이 존재하면 보존·전환 방식을 확인해야 하며 이를 무시하거나 삭제해 합계를 맞추면 안 된다. 이번 목업은 해당 레거시 값이 없는 예시이며 새 데이터 필드나 마이그레이션은 만들지 않았다.

## 예시 수치

| 지출 | 금액 | 결제자 | JH 분담 | 윤디 분담 |
| --- | ---: | --- | ---: | ---: |
| 저녁 식사 | 120,000원 | JH | 60,000원 | 60,000원 |
| 택시 | 40,000원 | 윤디 | 30,000원 | 10,000원 |
| 카페 | 20,000원 | JH | 5,000원 | 15,000원 |
| 합계 | 180,000원 | | 95,000원 | 85,000원 |

JH 결제 140,000원 − 분담 95,000원 = 받을 돈 45,000원. 윤디 결제 40,000원 − 분담 85,000원 = 보낼 돈 45,000원. 따라서 송금 안내는 윤디 → JH 45,000원이다. 1인 평균은 90,000원이지만 실제 분담액과 같다고 표시하지 않는다. 이 값들은 흐름을 설명하는 가상 예시이며 운영 여행에 저장하지 않았다.
