# 오늘의 여행 가독성·버튼·지출 상세 개선 목업

2026-11-01 · 이미지 목업만 제작 · 사용자 선택 대기

사용자가 첨부한 실제 화면을 기준으로 다음 문제를 전달했다: 장소/시간 글씨가 크고 두꺼움, 다음 장소와 시작 위치 버튼의 디자인 톤 불일치, 텍스트만 나열한 이날 지출 상세의 낮은 가독성. 기존 흰색·남색·노랑·파스텔 파랑/분홍을 유지하면서 작은 글자 계층과 재사용 가능한 컬러 아이콘, 금액 시각화를 탐색했다.

## 표시 순서

아래 번호는 이 대화에 생성 이미지가 실제 표시된 순서다. 순차적으로 독립 생성했으며 이전 생성 이미지를 다음 호출의 입력으로 사용하지 않았다.

1. [compact-overview.png](compact-overview.png)
2. [timeline-flow.png](timeline-flow.png)
3. [visual-summary.png](visual-summary.png)

각 이미지는 하나의 디자인 방향에서 오늘의 여행 메인과 지출 상세 두 상태를 함께 보여준다. 요청한 뷰포트는 각각 390×844, 보드는 820×884다. 생성 이미지의 실제 픽셀 크기와 프롬프트의 CSS 크기는 다를 수 있다.

정확한 최종 프롬프트, 생성 도구 원본 경로, 표시 순서, 보존 파일 경로, SHA256은 [generation.json](generation.json)에 기록했다. 내장 image_gen으로 T2I 생성했으며 이미지 입력은 없다. 프로젝트의 T2I 기본 지침을 따랐고 사용자 첨부 4장은 문제 범위와 이후 비교를 위한 기록으로만 보존했다. 저장 도우미 사용 후 매 호출에서 반환된 정확한 원본과 보존본의 SHA256을 대조했다. 기존 파일을 덮어쓰지 않았다.

## 다음 구현의 경계

- 이번 작업은 이미지 목업 제작과 프로젝트 작업 지침 갱신만 포함한다. 앱 소스·운영 여행 데이터는 수정하지 않았고 빌드·배포하지 않았다.
- 선택된 목업이 나오기 전에는 구현하지 않는다. 번호 선택이 추가 다듬기인지 구현 요청인지 사용자의 실제 문맥을 따른다.
- 현재 선택된 안은 없다. 서로 다른 안의 일부를 합치거나 추가 수정하면 그 조합을 다시 목업으로 확인한 뒤 구현한다.
- 메인 화면 목업으로 확인하지 않은 상세 창·버튼·상태까지 임의 구현하지 않는다. 해당 목업이 없는 범위는 사용자에게 먼저 확인한다. 이 요구를 [프로젝트 지침](../../../AGENTS.md)의 `구현 전 목업 확인 (2026-11-01 사용자 요청)`에 저장했다.
- 실제 구현 시 장소별 사진이나 개별 랜드마크 삽화를 새로 요구하지 않는다. 기존 카테고리 컬러 아이콘·공통 버튼·시간·이동·지출 컴포넌트로 구현할 수 있는 표현을 확정한다.
- 날짜·장소·금액은 목업 예시다. 전체 누적 286,800원 안에 사전구매 195,600원이 포함된다. 이날 44,000원은 예시 식비 32,000원과 교통 12,000원으로 구성한다. 환불 값·예약 유무·일정 개수 등 생성된 예시를 실제 데이터 계약으로 추가하지 않는다.
- 구현 시 현재 여행의 실제 날짜·금액·분류·권한·예약·목록에서 계산하고, 지정한 폰트/굵기/행 높이는 실제 모바일 뷰포트로 비교한다. 이미지 생성 결과가 코드나 기능 검증을 대신하지 않는다.
