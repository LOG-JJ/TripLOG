# 지출 기록 / 지출 추가 구현 검증

## 후속 크기·톤 보정

사용자 피드백에 맞춰 기존 TripLOG 로고와 노란 강조/짙은 테두리로 통일했다. 390/360/320px에서 금액 행 46px, 숫자 22px, 가로 넘침 없음과 화면 안의 저장 버튼을 확인했다. 금액 입력에 파란 개별 포커스 링이 생기지 않으며 부모 영역은 옅은 노란색으로 표시된다.

JPY 2,800 → 26,600원, 연속 입력 JPY 1,200 → 11,400원, KRW 4,500 저장을 재확인했다. 빈 환율은 입력 안내로 표시하고 새 기록을 열면 저장된 환율 또는 기존 기본 환율을 사용한다. 320px에서도 통화 팝업이 화면 밖으로 나가지 않는다. 아래 최초 검증의 분홍/파랑 독립 테마에 관한 설명은 초기 버전 기록이다.

보정 배포: `03571a85.triplog-5qs.pages.dev`. 운영 주소에서 수정한 4개 파일이 로컬 빌드와 일치하고, 금액 행 46px/숫자 22px 스타일이 적용됐으며 JavaScript 오류가 없는 것을 확인했다.

기준: `../20260915/triplog-expenses-ui-concept-20260915.png`. Image Gen으로 한 번 생성한 두 화면의 구성과 색상, 입력 순서를 구현 기준으로 사용했다. UI는 기존 정적 앱의 실제 HTML/CSS/JavaScript이며 목업 이미지를 화면에 붙이지 않았다.

## 필요한 차이와 문구 검토

- 날짜/연도/건수/금액/분류는 실제 저장된 데이터에서 계산한다. 샘플 이미지의 수치나 여행 날짜를 하드코딩하지 않는다. 항공은 기존 교통 분류를 유지한다.
- 상단에는 목업의 가상 알림 기능 대신 기존 동기화와 더보기 기능을 유지한다.
- 실제 지원하는 검색 범위를 설명하도록 ‘장소’ 대신 ‘메모’를 안내한다. ‘환율 수정’, 필터 결과 합계/초기화는 실제 입력 및 검색에 필요한 보조 기능이다.
- 모바일에서는 필터/정렬을 한 버튼으로 접고, 여행 기간 안내를 줄이며 요약을 두 열로 배치한다. 표는 날짜/내용/보조 정보/금액의 목록으로 전환한다. 작성 창에는 같은 입력 순서와 고정 저장 영역을 사용한다.
- 여행 일정은 `Day 1 · 9.25`, 결제일은 `09.15 (화)`처럼 공간에 맞춰 표시한다. 저장값은 기존 ISO 날짜 그대로다.
- 작은 분홍 글자는 명암 대비를 위해 #bd296d로 보정했다. 본문 대비 16.73:1, 보조 글자 4.79:1, 분홍 선택 글자 5.35:1 이상을 확인했다. 분홍 아이콘/브랜드/진행 막대는 목업의 포인트를 유지한다.
- 핵심 제목/탭/CTA/입력 항목의 문구와 순서를 비교했으며 위의 기능 및 반응형 차이 외에 새로운 홍보 문구나 섹션은 추가하지 않았다.

## 동작 확인 결과

- JPY 2,800 × (950원 / 100엔) = 26,600원 저장.
- 저장 후 계속: 금액/내용 초기화, 통화/환율/일정/결제일/결제 방식/결제한 사람 유지. 다음 JPY 1,200을 11,400원으로 저장.
- 해외 여행의 KRW 4,500 및 국내 여행의 KRW 9,900 입력/저장/새로고침 보존.
- 저장된 USD 200, 환율 1,300인 기록 수정 시 원래 통화/환율 유지. USD 201 → 261,300원으로 수정하고 여행의 JPY/950 기본 설정 유지.
- 수정 취소 시 기존 금액과 여행 통화 설정 유지.
- 검색, 카테고리, 시기 탭, 최신순/금액 정렬, 검색 결과 합계, 필터 초기화 확인. 모바일 접힌 필터에서도 교통 4건 선택/초기화 확인.
- 빈 금액 검증 시 저장 차단 및 올바른 금액 필드로 초점 이동.
- 같은 시점에 두 번 제출해도 지출은 한 건만 저장.
- 달력에서 체크아웃을 선택하여 3박 비용을 95,000원씩 나누고 총 285,000원 유지.
- 영수증 검토 → 새 입력 화면 → 저장 시 가맹점, JPY 금액, 원화 환산, 날짜, 현금 여부, 영수증 메타데이터 전달 확인. 이 검증은 고정된 OCR 결과를 사용했으며 인식 엔진의 정확도를 재평가하지 않았다.
- 콘솔 JavaScript 오류 없음. 변경 JavaScript 문법 검사, 기존 좌표 캐시 5개 회귀 및 여행 도우미 회귀 검사 통과.

## 화면과 방법

- 실제 IAB의 기존 지출 추가 화면을 먼저 읽고 캡처했다. 작성 중인 사용자 입력창을 유지하기 위해 기능 검증은 독립된 Playwright Chromium 컨텍스트에서 수행했다.
- 인증과 클라우드 통신은 로컬 테스트 컨텍스트에서만 대체하고 테스트 여행/지출을 사용했다. 운영 데이터는 테스트로 수정하지 않았다.
- 목업 전체의 원본 크기 1536×1024에서 데스크톱을 캡처하고, 입력 창을 별도로 캡처했다.
- 모바일 390×664 및 폭 390/360/320, 높이 844에서 확인했다. 페이지/요약/입력 창의 가로 넘침 없음. 320px에서도 저장 버튼이 화면 안에 유지되며, 664px 높이의 첫 화면에서 지출 행이 추가 버튼 위로 노출되는 것을 확인했다.
- 모바일 테스트는 브라우저 에뮬레이션이다. 실기기의 가상 키보드 및 운영체제 동작을 직접 테스트했다고 간주하지 않는다.

## 운영 반영

- Cloudflare Pages `triplog`의 `main`에 직접 배포했다. 배포 ID: `e6b75de4-4168-43d0-b01d-4f53dfe8f352`.
- [운영 지출 화면](https://triplog-5qs.pages.dev/Travel?page=budget)에서 HTTP 200, 앱 준비 상태 `true`, 변경한 13개 파일의 SHA-256이 로컬 빌드와 일치함을 확인했다.
- 별도 IAB 탭에서 실제 운영 지출 기록과 지출 추가 화면을 열어 새 표, 필터, 편집 가능한 결제 금액, 카테고리 버튼, 저장 후 계속을 확인했다. 검증 탭에서는 지출을 저장하지 않았다.
- 원래 사용자 탭의 입력창은 유지했고, 확인을 위해 만든 탭은 닫았다.
