## 공통 디자인 기준

흰 바탕, 진한 남색 글씨와 테두리, 노란 주요 동작, 연한 파랑·분홍 보조색, 작은 오프셋 그림자를 사용한다. 기존 프로젝트의 색상 사용 방식과 Noto 소분류 아이콘 카탈로그를 실제 구현에 재사용한다. 개별 여행지 스티커나 새 장식 그림을 제작하는 구조로 만들지 않는다.

큰 표지 삽화와 설명 문장은 줄이고 항목·상태·조작에 공간을 쓴다. 중요한 상태에는 색 이외에 숫자·체크·라벨도 함께 사용한다. 하단 내비게이션은 기존 구조를 유지한다.

## 여행 도구

현재 준비물, 포켓노트 HTML 저장, 캘린더 파일 저장, 여행지 시간대 기능을 중심으로 정리한다.

1. **메인**: 준비물 3/7과 남은 항목을 먼저 표시한다. 체크·추가·전체 편집을 가까이 둔다. 오프라인 여행정보, 캘린더 파일 저장, 시간대는 아래에 간결하게 배치한다.
2. **준비물**: 전체/남은 항목 필터, 즉시 체크, 인라인 추가·수정. 체크마다 큰 저장 버튼이나 반복 확인을 요구하지 않는다.
3. **오프라인 여행정보**: 일정·예약번호·경비 포함 여부를 고른 후 독립 HTML 파일로 저장한다. 저장 범위를 작은 미리보기로 보여준다.
4. **PC**: 왼쪽에 준비물, 오른쪽에 파일 저장과 설정. 새 사이드바를 만들지 않는다.

### 기능 의미와 상태

- 예시 7개 중 여권/eSIM/충전기가 완료이므로 3/7이다. 카운트는 원본 데이터에서 계산한다.
- 빈 준비물 목록에는 짧은 안내와 항목 추가를 표시한다. 모두 완료하면 완료 수를 유지하고 남은 목록이 없음을 표시한다.
- 체크/수정 저장 실패 시 성공으로 확정하지 않고 재시도할 수 있게 한다. 여행 전환 시 다른 여행의 목록이 섞이지 않아야 한다.
- 캘린더는 ICS **파일 저장 및 가져오기** 기능이다. 계정 연결·자동 동기화로 표현하지 않는다.
- 포켓노트는 다운로드한 HTML이다. 외부 지도·예약 링크 열기는 연결이 필요할 수 있다.
- 경비는 **기록된 지출**을 포함한다. 생성 이미지에 예상 경비 같은 문구가 있더라도 예상 예산 기능을 추가하는 뜻으로 해석하지 않는다.
- 파일 용량은 실제 생성 후에만 표시한다. 생성 이미지의 임의 용량은 요구사항이 아니다.
- 아무 콘텐츠도 선택하지 않으면 저장할 항목을 선택하게 한다. 저장 성공·실패·생성 중 상태를 구분하고 중복 클릭을 막는다.
- 예약지갑과 지출 대시보드를 도구 메인에 중복 배치하지 않는다. 날씨·주변검색·새 외부 API는 이번 범위에 추가하지 않는다.

## 일정 분석

현재 `src/app/features/reports/report-workspace.js`의 일정 분석을 기반으로 한다. 날짜 필터, 일정 수·체류·이동 합계, 장소별 체류시간 정렬, 일정 편집 연결을 유지하면서 비교 구조를 개선한다.

1. **전체 여행**: 계획 일정 수 / 입력된 체류 / 기록된 이동을 간결하게 표시한다. 날짜별 체류와 이동을 같은 축의 수평 누적 막대로 비교한다. 날짜를 누르면 해당 날짜 상세로 이동한다.
2. **날짜 상세**: 같은 날짜의 카운트·합계와 장소 목록. 일정순/긴순/짧은순 정렬을 제공한다. 선택과 정렬은 복귀 시 유지한다.
3. **미입력 항목**: 체류 미입력 장소와 이동시간 미입력 구간을 별도로 보여주고 해당 입력 화면으로 연결한다.
4. **PC**: 왼쪽 날짜별 비교, 오른쪽 장소별 순위. 동일한 값과 공통 축을 유지하며 모바일에서 전체를 가로로 압축하지 않는다.

### 수치와 상호작용 계약

- 항상 **계획 기준**을 표시한다. GPS 방문 기록이나 실제 체류시간으로 표현하지 않는다.
- 일정 수는 숙소를 포함한 전체 일정 개수다. 체류 합계·장소 순위는 기존 의미대로 숙소를 제외한다. 분모가 다르므로 짧은 보조 라벨을 둔다.
- 체류는 입력된 시작/종료 시간으로 계산한 유효한 값만 합산한다. 이동은 실제 연결된 구간의 모든 leg를 합산한다.
- 겹친 일정의 체류시간은 개별 항목의 합이다. 이를 하루의 실제 활동시간·여유시간·혼잡도로 해석하지 않는다.
- 미입력은 null/미정 상태이며 0분과 구별한다. 비교 막대에 예상 길이를 임의로 채우지 않고 별도 표시를 둔다.
- 순위는 동일한 기준의 기간 필터를 적용한다. 미입력 항목은 마지막에 유지한다.
- 출발 항목 없는 첫 일정, 삭제·이동 후 오래된 구간 참조, 여러 교통수단 leg, 날짜 경계와 자정 넘김은 기존 공통 도메인 기준으로 처리한다.
- 막대는 0부터 시작하고 공통 선형 축을 사용한다. 단위와 직접 라벨을 표시한다. 3D·과장된 비율·hover만 가능한 설명은 쓰지 않는다.
- 미입력 표시를 누르면 어떤 항목이 빠졌는지 먼저 확인한 뒤 기존 시간·이동 편집기로 연결한다. 운영 데이터는 목업 제작 중 수정하지 않는다.
- 별도 일정점검 메뉴, 자동 순서 변경·지연 보정, 장문의 분석 평가 문장을 추가하지 않는다.

### 데이터가 적거나 없는 상태

- 일정 없음: 추가 진입 버튼과 간단한 안내.
- 일정은 있지만 시간 미입력: 일정 수는 표시하되 시간은 미입력으로 구분하고 관련 입력 진입을 제공.
- 이동 없음과 이동시간 미입력: 서로 다른 상태로 구분.
- 로딩/조회 실패: 과거 수치를 최신 성공 결과처럼 보여주지 않음.
- 긴 장소명·다수 일정: 핵심 숫자와 버튼을 보존하고 목록을 세로로 확장.
