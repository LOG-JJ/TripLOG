# 예약 지갑 금액 입력·지출 연동 제안

이미지 목업 단계의 동작 제안이다. 현재 예약 데이터 스키마·앱 코드는 변경하지 않았다.

- 예약 지갑은 현재 사용·숙박 중인 예약을 먼저 표시하고, 종류별로 번호 복사·원본 예약 열기·주소·일정 연결을 제공한다.
- 예약 총액과 실제 결제 기록을 구분한다. 현장 결제 예정 금액은 지출 합계에 넣지 않는다.
- 결제 기록을 저장할 때 지출 자동 연동을 켜면 결제별 지출을 연결한다. 한 번에 전액 결제하면 1건, 예약금·잔금을 따로 내면 실제 결제 날짜별로 각각 기록한다.
- 이미 사전구매에서 가져온 예약은 해당 지출을 재사용한다. 별도 지출을 기록했다면 사용자가 기존 항목을 선택해 연결하며 이름·금액이 비슷하다는 이유로 자동 합치지 않는다.
- 실제 결제 금액·결제일·결제자·수단을 바꾸면 연결된 지출을 같은 ID로 갱신한다. 예약 총액만 수정한 경우 실제 결제 내역을 덮어쓰지 않는다.
- 예약 이용일과 결제일은 별도다. 여행 전 결제는 기존 사전구매 분류에 실제 결제일을 함께 보관한다. 종류에서 지출 분류를 제안하되 수정할 수 있다.
- 외화 원금·통화·기록 당시 환율을 함께 보관한다. 목업의 100엔=950원은 예시 환율이다. 36,000엔=342,000원, 예약금 10,000엔=95,000원, 미결제 잔금 26,000엔은 지출에서 제외한다.
- 예약 삭제·취소와 지출 삭제·환불을 분리한다. 실제 환불을 기록할 때 기존 지출 이력을 보존하면서 환불 금액을 반영한다.
- 예약과 연결 지출의 저장은 하나의 변경으로 처리하고, 실패하면 한쪽만 남지 않도록 한다. 저장 재시도에서도 동일한 결제·지출 연결을 재사용한다.
- 다음 구현 시 공유 도메인 명령, 브라우저·CLI 검증, 정규화·동기화·백업 및 원본 지출에서 생성되는 예약 표시까지 같은 계약으로 확장해야 한다. 페이지 렌더링만으로 지출을 생성하지 않는다.

생성 방식은 입력 이미지 없는 T2I이며 원본 경로·프롬프트·해시는 generation.json에 보존한다. 화면 속 이름·예약번호·금액은 목업용 예시다.
