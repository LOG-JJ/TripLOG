## 공통 디자인 기준

- 기본 바탕 #FFFFFF, 본문 #0B1020, 주요 행동·선택 #FFF05A, 보조 행동 #BCE6FB, 브랜드 #F7AFC7.
- 굵은 Pretendard 계열 제목, 검정 약 2px 테두리, 9–12px 모서리, 필요한 곳에 작은 검정 그림자.
- 기본 화면의 하단 메뉴: 개요 / 일정 / 지출 / 리포트 / 더보기. 더보기에서 나의 여행·경비 정산·준비물·멤버·기록·설정으로 연결한다.
- 추가·수정·관리 작업은 닫을 수 있는 집중 화면으로 구성하고, 주요 저장·반영 버튼을 하단에 둔다.
- 아이폰 14 Pro의 393px 폭을 중심으로 한 모바일 설계. 원본 PNG마다 생성된 캔버스 치수가 다르며, 실제 구현 시 비율을 늘려 변형하지 않고 화면과 시트 높이에 맞춰 재배치한다.
- 아이콘은 기존 Phosphor 계열, 로고는 기존 일정 화면을 기준으로 맞춘다. 실제 구현에서 텍스트와 컨트롤은 HTML로 구성한다.

## 예시 데이터

현재 기준일 2026-09-13(일), 서울 주말 여행은 9월18일(금)부터20일(일)까지 2박3일이다. 출발 D-5이며 멤버는 나·민지·준호 세 명이다.

예산600,000원 중 사전구매312,000원, 남은 예산288,000원, 사용률52%. 숙소180,000원·교통72,000원·식비36,000원·관광24,000원으로 합계를 통일했다. 결제일별 리포트는 여행 전 실제 결제일을 보여주는 시안이다. 카테고리 정수 비율58/23/11/8%는 합이100%가 되도록 조정했다.

정산은 1인104,000원 부담, 나180,000원·민지96,000원·준호36,000원 결제 예시다. 민지8,000원·준호68,000원을 나에게 보내는 안내와 일치한다.

## 구현에 이어갈 때

- 기존 여행·지출·정산 데이터와 동기화 흐름을 보존하면서 공통 헤더·내비게이션·폼부터 적용한다.
- 여행 전 결제일과 일정에 기록하는 일자는 구분한다. 현재 저장 구조와 맞추는 작업은 구현 단계에서 검토한다.
- 영수증 인식은 기기에서 처리하고 결과 확인 후 입력에 반영하는 흐름을 유지한다.
- 정산은 금액 안내이며 실제 송금 기능을 가정하지 않는다.
- 초대 링크는 예시처럼 축약해서 표시하되, 복사 동작에는 실제 링크 전체를 사용한다.
- 저장 기록의 불러오기·삭제와 초기화는 기존 동작 및 확인 흐름을 보존한다.
- 오류·빈 화면·키보드·회원가입·초대 수락·예약 상세 등 보조 상태는 이 세트의 공통 규칙으로 구현한다.
- 이미지에 묘사된 새로운 정보 배치와 제어 방식은 개편 제안이며 현재 배포된 기능을 의미하지 않는다.

## 참고 자료

실제 프로젝트의 Travel.html, 페이지 라우터, 기존 일정 디자인 문서와 승인된 목업 두 장을 확인했다. 개요 화면은 로컬 샘플 화면 캡처도 이미지 생성에 첨부했다. 실제 계정이나 사용자의 여행 내역은 목업 데이터로 사용하지 않았다.

13개의 PNG를 직접 확인해 제목·주요 행동·색상·하단 메뉴와 예시 금액을 점검했다. 실행 코드는 수정하지 않았으며 목업과 검토 자료를 추가했다.
