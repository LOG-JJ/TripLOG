# 삭제 UI 개선 — 2026-10-17

요청: 앱의 삭제 기능과 문구를 모두 취합하고, 각각의 목업을 만든 뒤 간결한 디자인으로 구현합니다.

## 기존 화면에서 확인한 문제

390×844 모바일에서 한 줄짜리 일정 삭제 확인창이 350×675.19px로 표시되었습니다. PC(1440×1000)에서도 420×800px로 늘어나, 대부분의 영역이 빈 공간이고 실행 버튼은 하단에 멀리 떨어져 있었습니다. 공통 폼 대화상자의 레이아웃을 확인창도 공유하는 구조입니다.

## 목업과 제작 기록

- 생성 방식: **T2I**. 입력 이미지: **없음**.
- [최종 생성 프롬프트](prompts.md), [전체 상태와 정확한 문구](brief.json).
- [원본 반환 경로·SHA256 기록](generation.json): 다섯 원본 모두 저장본과 해시가 일치하며 기존 파일을 덮어쓰지 않았습니다.
- 각 목업 보드 안의 상태는 모두 별도의 삭제 상황입니다. 4개 보드에 확인창 16개, 마지막 보드에 편집 중 제거 상태 2개를 담았습니다.
- 목업에서 생성된 배경 화면은 확인창의 크기를 보여주는 참고 배경입니다. 구현 범위는 삭제 확인창과 제거 컨트롤이며, 기존 앱 내비게이션·여행 데이터·각 편집기 구조는 유지합니다.

검색어·지출 내용 입력 지우기, 필터 초기화, 장소 검색 선택 해제는 저장된 데이터 삭제가 아닙니다. 즉시 입력값만 바꾸는 기존 동작을 유지합니다. 연결 설정 초기화도 인증 연결 설정을 바꾸는 별도 기능으로서 여행 삭제로 취급하지 않습니다. 내부 캐시·객체 정리와 저장소 마이그레이션에는 사용자용 삭제 창을 추가하지 않습니다.

일정·지출에서 유래한 예약은 원본 편집기로 연결되므로 원본의 일정·지출 삭제 경로가 적용됩니다. 직접 등록한 예약에만 예약 전용 확인창이 적용됩니다. 정산 멤버가 결제한 지출이 있으면 기존의 결제자 변경 안내를 유지합니다.

## 구현 기준

- 내용 높이에 맞는 가운데 확인창. 모바일과 PC에서 동일한 구성, 최대 폭 342px.
- 질문 18px, 대상·설명·버튼 14px. 버튼 높이 최소 44px.
- 흰 표면, 얇은 윤곽, 작은 그림자, 흰 취소 버튼과 붉은 실행 버튼.
- 대상이 없으면 대상 줄, 영향 안내가 없으면 안내 줄을 생략합니다.
- 취소를 처음 포커스하고, Escape·바깥 클릭도 취소로 처리합니다. 닫을 때 원래 컨트롤로 포커스를 돌립니다.
- 긴 이름·댓글은 실제 내용을 안전한 텍스트로 표시합니다. 좁은 화면·큰 글자에서도 버튼이 잘리지 않아야 합니다.
- 동작 중 여행·대상·연결 상태가 바뀌면 새 대상을 지우지 않도록 재확인합니다. 완료 안내는 저장 성공 후 표시합니다.

공통 구현은 [confirmation.js](../../../src/app/ui/confirmation.js), 외형은 [redesign.css](../../../src/styles/redesign.css), 회귀 검증은 [delete-dialogs-browser-regression.js](../../../scripts/delete-dialogs-browser-regression.js)에 있습니다. 각 기능은 `TripLog.ui.confirmation.ask({ kind, subject, message })`로 정확한 대상과 영향만 전달합니다. 복원·소유권 이전 등 비삭제 확인도 같은 작은 확인창을 사용하며 동작 이름과 중립색 버튼을 표시합니다.
