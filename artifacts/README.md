# TripLOG 산출물

목업, 제작 원본, 프롬프트, 검증 자료와 임시 파일을 이 폴더 아래에서 관리합니다. 이 폴더는 앱 배포·오프라인 캐시에 포함하지 않습니다.

| 폴더 | 보관 대상 | Git |
| --- | --- | --- |
| `design/YYYYMMDD-topic/` | 필요한 목업 원본, 선택 기록, 최종 프롬프트, 입력 이미지·SHA256, 삽화 재생성 원본 | 보존할 자료를 추적 |
| `qa/YYYYMMDD-topic/` | 완료된 검증 요약과 대표 화면 | 필요한 최종 근거만 추적 |
| `tmp/YYYYMMDD-topic/` | 임시 스크립트·로그·캡처·PDF·ZIP·실험 결과 | 제외 |

새 작업은 날짜와 주제를 조합한 하위 폴더를 사용합니다. 기존 자료는 주제별 이름 또는 날짜별 목업 묶음을 유지합니다. 프로젝트 구조·상태·운영 지침은 기존 `docs/`에 보관합니다.

## 보존과 정리

- 생성 호출이 반환한 정확한 원본을 보관하고, 저장본과 원본의 SHA256을 대조합니다. 최종 프롬프트, 생성 방식, 입력 이미지 역할, 선택 여부를 함께 남깁니다.
- 현재 앱에서 쓰지 않는 이미지도 재생성 입력이면 `design`에 보존합니다. 실행 자산에는 실제 화면·설치 아이콘·기능이 참조하는 파일만 둡니다.
- 동일 파일은 해시를 확인한 뒤 한 사본으로 통합합니다. 옮기거나 통합한 파일은 문서 링크와 실행 가능한 생성 도구의 경로를 함께 갱신합니다.
- 작업 중의 모든 화면 캡처를 영구 보관할 필요는 없습니다. 최종 결과를 증명하는 요약과 대표 화면만 `qa`에 남깁니다.
- `dist/`, 의존성, 서비스 워커 및 서버 공용 모델의 빌드 출력은 각 도구가 관리합니다. 마이그레이션과 라이선스 파일은 일반 임시 파일로 정리하지 않습니다.

## 테스트 출력

브라우저 테스트는 `scripts/helpers/artifact-output.js`를 통해 기본적으로 한국 시간 기준 `tmp/<실행일>/<테스트명>/`에 출력합니다. 실행 묶음을 지정하려면 PowerShell에서 다음처럼 실행합니다.

```powershell
$env:TRIPLOG_ARTIFACT_RUN = '20261016-repository-cleanup'
npm run test:browser
Remove-Item Env:TRIPLOG_ARTIFACT_RUN
```

기존 `TRIPLOG_UI_SNAPSHOT_DIR` 또는 `TRIPLOG_TEST_OUTPUT`을 명시하면 해당 경로를 사용합니다. 새 경로도 이 폴더 아래에 지정하는 것을 기본으로 합니다. GitHub Actions는 `artifacts/tmp/`를 테스트 결과로 수집합니다.

`npm run artifacts:check`는 루트·`docs/`의 산출물, `design/` 내부의 QA·브라우저 캡처·exports 폴더, 영구 보관 영역의 로그·PDF·ZIP과 QA 실행 스크립트를 검사합니다. 재생성에 필요한 디자인 도구와 원본·프롬프트는 `design/`에 보존합니다. 같은 검사를 `npm run test:source`와 `npm test`에서도 실행합니다.

2026-11-04에 전체 캡처·PDF·실행 뷰어·기하 진단 등 1,316개를 `tmp/`로 옮기고, 디자인 자료에 섞인 완료된 QA 56개를 `qa/`로 분리했습니다. 임시 자료는 로컬에 남으며 Git에서 제외됩니다. 이를 가리키는 과거 기록의 링크는 해당 로컬 자료가 있을 때만 열립니다. 원본 생성 기록과 이전 감사 JSON 내부의 경로는 당시 출처로 유지합니다. 현재 위치는 아래 이동 목록에서 확인할 수 있습니다.
