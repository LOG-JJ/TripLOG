# TripLOG

TripLOG는 여행 일정, 지출, 정산, 저장 기록, 리포트를 관리하는 한국어 여행 앱입니다. 프런트엔드는 `Travel.html`, `styles.css`, `app.js`, `src/app/`의 브라우저 전역 구조를 유지하며, 협업 버전은 IndexedDB 저장소와 Supabase 명령 API를 사용합니다. npm은 버전이 고정된 공동 메모·일정 드래그 라이브러리, 테스트, 배포 자산 생성에 사용합니다.

자동 저장·공동 편집 구현과 실제 검증 범위, 운영 전환 순서는 [협업 구현 및 배포 기록](docs/collaboration-implementation.md)을 확인하세요. 저장 상태 버튼은 상태·충돌·복구 화면을 엽니다. 변경 전송을 시작하는 수동 동기화 버튼은 없습니다.

앱 갱신도 자동입니다. 새 앱을 백그라운드에서 준비하고 작성 중인 입력과 기기 저장이 끝난 뒤 적용합니다. 사용자가 버전을 고르거나 갱신 버튼을 누를 필요가 없으며, 미전송 변경과 초안은 유지합니다. 빌드 지문은 소스 내용에서 자동 생성됩니다.

## 실행

접속 주소: [TripLOG 내 여행](https://triplog-5qs.pages.dev/Travel?page=start). 이 주소의 도메인을 근거로 배포 도구를 선택하지 않습니다.

앱은 여권 모양의 **내 여행 보관함**에서 시작합니다. 여행 이름·여행지 검색과 예정/진행/지난 여행 필터를 사용하고, 표지를 눌러 해당 여행의 개요를 엽니다. 기존 `page=overview` 홈 북마크도 여행 ID가 없으면 보관함으로 연결됩니다. 선택한 여행의 URL에는 `trip`이 포함되어 새로고침·뒤로가기에서도 선택을 유지합니다. 상단 로고로 보관함에 돌아갈 수 있으며, 여행 메뉴에서 정보 수정과 기존 여행 바꾸기/삭제 흐름을 사용할 수 있습니다. 설치형 앱의 시작 주소도 보관함입니다.

선택한 [1안 원본](artifacts/design/20261003/triplog-home-passport-library-20261003.png)과 [구현 비교 및 QA](artifacts/design/home-passport-20261003/design-qa.md)를 보관합니다. 목업의 예시 여행은 운영 데이터로 넣지 않습니다. 격리된 시각 미리보기는 `node scripts/preview-trip-library.js`, 기능 검증은 `node scripts/trip-library-browser-regression.js`로 실행합니다.

## 배포 절차

2026-09-29 사용자 확인 기준으로 **Git 커밋·푸시 → 연결된 자동 배포**를 사용합니다. 사용자는 Supabase 연동을 사용한다고 확인했습니다. 작업 절차는 [AGENTS.md](AGENTS.md)를 따릅니다.

원격 `main`의 변경을 반영하고 관련 테스트와 `npm run build`를 완료한 뒤 변경을 커밋·푸시합니다. 과거 문서의 Cloudflare Pages·Wrangler 직접 업로드는 이력이며 현재 기본 절차가 아닙니다. Git 푸시 성공과 자동 배포 완료는 별도로 확인·보고합니다.

### 로컬 실행

```powershell
npm ci
npm run prepare:sync
npm run preview
```

브라우저에서 `http://127.0.0.1:18080/Travel.html`을 엽니다. 특정 화면은 `Travel.html?page=itinerary`, `Travel.html?page=budget`처럼 `page` 쿼리로 열 수 있습니다. 프런트엔드만 실행해도 실제 운영 서버에 연결될 수 있으므로, 자동 테스트는 별도 계정·브라우저·가상 서버 응답을 사용합니다.

## 주요 기능

- **다중 여행 관리**: 여러 여행을 만들고 전환하며, 국내/해외 모드와 국가/도시/기간을 여행별로 저장합니다.
- **정산 이름 수정**: 멤버별 정산의 이름 옆 연필 또는 `멤버 추가·관리`에서 기본 결제자의 정산 이름을 수정합니다. `내 프로필 이름 사용`으로 로그인 이름을 불러온 뒤 저장할 수 있습니다. 이름은 여행별로 보관하며, 결제자 선택·분담표·송금 안내에도 동일하게 표시합니다. 기존 결제자 연결과 분담 금액은 유지됩니다.
- **여행 개요**: 여행 정보·예약·경비·대표 일정·준비물은 공통 카드 프레임과 제목 행을 사용하고 내용/크기 규격만 다릅니다. 첫날 또는 오늘의 대표 일정은 시간순 최대 5개를 표시합니다. 경비 카드는 약 270px 높이에 합계·건수·1인 평균·항목별 비중을 압축하고, 항목을 누르면 해당 분류의 지출 목록을 엽니다. PC에서는 대표 일정 카드와 높이를 맞춥니다. [공통 카드 구현·검증](artifacts/design/travel-cost-card-visual-20261012/design-qa.md).
- **여행 경비**: 개요·지출·리포트에서 기록한 지출의 누적 금액, 건수, 1인 평균을 표시합니다. 사전구매·날짜 미정·기간 밖 기록도 포함하고 환불은 차감합니다. 외화 지출은 저장된 원화 환산 금액을 합산합니다. 지출의 추가·수정·삭제와 멤버 변경을 바로 반영하며, 검색·필터는 전체 경비를 바꾸지 않습니다. 계획 예산 입력, 사용률, 남은 예산과 초과 경고는 사용하지 않습니다. 과거 예산 값은 백업 호환성을 위해 데이터에 보존합니다.
- **오늘의 여행**: 개요의 `오늘의 여행 시작`에서 다음 미완료 장소·길찾기·완료율·선택한 날짜의 여행 경비를 확인합니다. 경비를 누르면 해당 날짜·전체 누적·사전구매 금액을 확인할 수 있습니다.
- **일정 점검과 지연 조정**: 겹치는 시간과 부족한 이동 시간을 찾고 0·15·30·60분 지연을 반영한 미리보기를 제공합니다. 완료·잠금 일정은 보호하며, 적용 후 한 번 되돌릴 수 있습니다.
- **예약 지갑**: 항공·숙소 사전구매와 일정 바우처를 모아 보고 직접 예약을 추가·수정·삭제합니다. 예약번호 복사, 예약 링크 열기, 일정 연결을 지원하며 지출을 중복 생성하지 않습니다.
- **숙소 일정 자동 추가**: 숙소 예약을 저장하면 여행 기간 안에서 체크인일부터 체크아웃 전날까지 하루에 하나씩 숙소 일정을 만듭니다. 사전구매와 직접 등록한 예약 모두 적용되며, 재저장 시 기존 일정을 재사용합니다. 기간을 줄이면 제외된 자동 일정을 정리하고, 날짜별로 수정한 도착 시각·메모는 유지합니다. 기존 예약도 수정 후 저장하거나 `일정에 추가`를 누르면 숙박일 전체가 반영됩니다.
- **여행 도구**: 여행지 시간대로 ICS 일정을 내보내고, 일정·예약번호·누적 경비 포함 여부를 선택하여 독립 HTML 포켓노트를 저장합니다. 포켓노트는 오프라인에서 읽을 수 있습니다. iPhone 캘린더 가져오기 안내는 ICS 다운로드 후 표시됩니다.
- **일정 관리**: 일차별 타임라인에서 시간과 장소를 확인합니다. `일정 추가`에서 장소 검색·직접 입력·시작/종료 시간·메모·티켓을 저장하고, 일정 사이 이동 정보를 눌러 길찾기 또는 이동 기록을 편집합니다. 국내여행은 네이버지도, 해외여행은 Google 지도로 자동 연결됩니다.
- **일정 순서 이동**: 손잡이를 잡으면 원본 카드의 크기와 잡은 위치를 유지하며 이동합니다. PC에서는 카드의 빈 영역도 잡을 수 있고, 모바일 본문은 화면 스크롤을 유지합니다. dnd-kit DOM 0.5.1의 정렬·자동 스크롤을 사용하며, 놓을 위치는 노란 삽입선과 작은 안내 라벨로 표시합니다. 이동 중에는 원본 카드를 부드러운 그림자로 띄우고, 주변 카드와 놓기 동작을 짧게 애니메이션 처리합니다. 이동 중에는 저장하지 않고 놓을 때 순서만 저장하므로 시간·내용은 바뀌지 않습니다. Escape로 취소하거나 `Alt + ↑/↓`로 이동할 수 있고, 동작 줄이기 설정을 따릅니다. 라이브러리는 앱에 포함하여 오프라인에서도 로드합니다.
- **일정 복사**: 일정 이름 옆 복사 아이콘으로 기존 장소·시간·메모·티켓을 같은 편집창에 불러옵니다. 날짜와 내용을 확인하고 `복사해서 추가`를 누르면 독립적인 새 일정으로 저장합니다. 이전 장소에서 오는 이동 정보와 연결 지출은 복제하지 않습니다.
- **일정 사이 지도와 길찾기**: 국내는 앱 안의 OpenStreetMap 지도에 출발지·도착지 핀을 표시하고 확대·축소·이동할 수 있습니다. 별도 가입·결제 등록·API 키가 필요하지 않습니다. 상세 자동차·대중교통·도보 길찾기는 네이버지도로 연결합니다. 이름만 저장된 장소도 여행 지역과 함께 자동 조회합니다. 기록된 이동 수단이 없으면 국내는 자동차를 기본으로 사용합니다. 조회 결과는 원본 일정·시간·좌표 선택을 덮어쓰지 않으며, 통신 실패는 다시 시도할 수 있습니다. 해외는 기존 Google 미리보기를 유지하고, 모바일 외부 지도에서 돌아오면 작성 중인 기록을 복원합니다.
- **일정 요약**: 일정 화면의 `일정 편집 / 일정 요약`으로 같은 화면의 목록을 전환합니다. 날짜별 시간 범위·장소·일정 수와 기록된 이동 시간을 표시하고, 펼치기·접기·해당 날짜 편집·전체 요약 복사를 제공합니다. 이동 시간은 같은 날의 인접 장소 사이에 직접 기록한 구간만 합산하며, 미입력 시각·이동 시간과 여행 기간 밖의 일정도 구분합니다. 요약 보기는 일정 데이터를 변경하지 않으며, 보기 방식과 펼친 날짜는 기기 세션에 보관합니다. 편집 화면의 날짜 목록 옆 목록 아이콘으로 기존 전체 일정 보기도 사용할 수 있습니다.
- **지도와 동선**: 국내는 일정 장소와 전체 동선을 앱 안 지도에서 확인하고, 번호 핀 아래에 구간별 네이버 링크를 표시합니다. 지도에는 확인된 장소 위치를 표시하며 실제 이동 경로는 네이버에서 확인합니다. Leaflet 1.9.4는 앱에 포함하고, 지도 타일은 현재 보이는 영역만 요청하며 OpenStreetMap 출처와 정상 HTTP 캐시를 유지합니다. 지도 오프라인 다운로드나 영역 사전 수집은 하지 않습니다. 해외는 Google 미리보기와 전체 경로를 사용합니다.
- **모바일 지도 열기**: 지도 아래 버튼은 선택된 지도 서비스로 직접 연결합니다. 돌아오면 세션에 임시 보관한 일정 입력값을 복원하고, 저장하거나 닫으면 임시 입력값을 삭제합니다.
- **지출 기록과 입력**: 목업을 기준으로 날짜·내용·카테고리·결제 수단·금액을 정렬하고 검색/필터/정렬을 제공합니다. 원화와 외화는 하나의 결제 금액 영역에서 입력하며, 환산 금액과 환율을 바로 확인합니다. `저장 후 계속`은 입력 조건을 유지하고 다음 지출을 받습니다. 설계와 검증은 `artifacts/design/legacy-ui/expense-ui-design.md`, `artifacts/design/legacy-ui/expense-ui-verification.md`에 정리했습니다.
- **지출 가계부**: 결제일·결제한 사람·결제 방식을 기록하고, 사전구매 항공/숙소 입력, 카테고리 필터, 검색, 정렬, 숙소 박수별 자동 분할을 지원합니다.
- **국내/해외 통화**: 해외 모드에서 통화, 환율, 외화 금액을 원화 지출로 환산합니다.
- **패킹 리스트**: 준비물 체크, 직접 추가·삭제, 순서 이동과 자동 저장을 제공합니다.
- **더치페이 정산**: 현재 여행 또는 저장 스냅샷을 기준으로 참여 멤버, 개인 지출, 항목별 N분의 1/직접 입력 분담, 송금 가이드를 계산합니다.
- **통계 리포트**: 카테고리별 지출 비율, 실제 결제일별 지출, 일자별 일정 수·체류·이동 시간을 보여줍니다.
- **저장/복원/백업**: 브라우저 저장소에 현재 여행과 스냅샷을 보관하고 JSON으로 내보내거나 가져올 수 있습니다.
- **보고서 출력**: 설정의 `PDF 저장`에서 일정·지출·전체 리포트를 A4 페이지로 미리 보고 저장합니다. 일정은 날짜별 시간표와 `날짜·시간·장소·이동·메모` 5열 상세 표를 담습니다. 상세 표는 프리텐다드와 짧은 셀 여백을 사용하며, 이동 열에 저장된 교통수단별 이모지와 실제 시간을 표시합니다. 복합 이동·주소·긴 메모도 보존하고 날짜 묶음과 열 제목을 페이지마다 다시 표시합니다. 지출은 항목별 비중·일자별 그래프와 **모든 지출 내역**을 담습니다. 기본값은 사전구매와 기간 밖 기록까지 포함한 전체 지출이며, 내보내기 화면에서 기간을 직접 선택할 수 있습니다. 긴 지출 표는 제목을 반복하며 다음 페이지로 이어지고 마지막에 합계를 표시합니다. 옵션은 원본 여행 데이터를 변경하지 않습니다.
- **여행·계정 설정**: 프로필, 여행 모드, 통화·환율, 공유 범위와 백업·복원을 관리합니다. 연결 설정은 고급 설정에서 확인합니다.

## 전체 화면 개편

PDF 내보내기는 일정 목업 4번(시간표형)과 지출 목업 1번(비중 시각화형)을 기준으로 구성했습니다. 지출 내역은 발췌하지 않으며 외화 원금·원화 환산금액, 환불과 긴 메모도 보존합니다. 오프라인에서도 같은 글꼴과 목적지 삽화를 사용하며, PDF 저장은 브라우저 인쇄 창의 `PDF로 저장`을 이용합니다. 예시 데이터만 사용하는 격리 미리보기는 `node scripts/preview-export-reports.js` (`http://127.0.0.1:18112/Travel?page=settings&trip=export-suncheon`), 계산·페이지 나눔·모바일·전체 내역 검증은 `npm run test:print`입니다.

`한눈에 보는 시간표`의 일정 블록은 프리텐다드로 시간·장소명·이동 정보의 크기와 굵기를 구분합니다. 짧은 일정은 한 줄, 일반 일정은 시간과 장소명을 위아래로, 긴 일정은 이동 요약을 하단에 배치합니다. 삽화와 글자 영역을 분리하고, 이동 요약은 실제 교통수단의 이모지와 시간으로 표시합니다. 전체 이동 비용·메모는 상세 표에 보존합니다. 일정이 겹치면 한 페이지의 날짜 수를 줄여 표시 폭을 확보하며, 한 날짜에 5개 이상 동시에 겹치는 경우 시간순 표를 사용합니다. 시간 비율과 원본 일정은 변경하지 않습니다.

지출 리포트는 **첫 장을 분석·요약 전용으로 사용하고, 상세 지출 내역은 항상 다음 장부터 시작**합니다. 첫 장은 총경비, 항목별·일자별 차트, 하루 평균과 최대 지출 요약으로 채웁니다. 하루 평균은 해당 리포트 합계를 여행 일수로 나누며, 하루를 선택한 경우에는 1일 기준입니다. 여행 날짜가 없거나 사전구매만 선택한 경우 평균은 `—`로 표시합니다. 최대 지출은 날짜 묶음 이전의 일자별 합계로 비교하고, 사전구매·날짜 미정이 가장 크면 해당 묶음의 이름을 표시합니다. 차트를 끈 경우에도 상세 표는 요약과 분리합니다.

`일자별 지출 현황`은 날짜·금액·퍼센트를 가로 행과 파스텔 비중 막대로 표시합니다. 비중은 전체 또는 선택한 기간의 **환불 반영 후 지출 합계**를 기준으로 소수점 한 자리까지 표시하며, 아주 작은 비중은 `<0.1%`로 표시합니다. 환불일은 0선 왼쪽에 음수로 표시하고, 합계가 0원 이하이면 비중은 `—`로 표시합니다. 사전구매·기간 밖 기록·날짜 미정도 포함하며 긴 여행은 최대 7개 묶음으로 합산합니다. 표시 비중의 합은 반올림에 따라 100%와 조금 다를 수 있습니다.

일정 내보내기에는 국가 목록에 의존하지 않는 **장소·활동 유형 삽화 50종**을 사용합니다. 한국어·영어·일본어·중국어 등 다국어 장소명, 일정 분류, 명시된 교통 예약 종류와 가져온 장소 유형을 참고합니다. 불명확한 장소는 일정 분류별 공통 그림을 표시하므로 어느 국가의 여행도 빠지지 않습니다. 그림은 유형을 표현하며 실제 건물의 외관을 재현한다고 가정하지 않습니다. 저장된 이동 구간은 도착 장소의 종류를 결정하지 않습니다. 이미지 파일을 앱에 포함해 실행 중 AI 호출이나 별도 비용 없이 사용하며, 이미지 로딩 실패 시 분류별 그림과 공통 여행 그림으로 순차 대체합니다. [제작 원본·검증 기록](artifacts/design/itinerary-art-world-20261012/README.md)과 `src/app/data/itinerary-art.js`, `src/app/shared/itinerary-art.js`에서 목록과 규칙을 확인할 수 있습니다.

여행 헤더는 **모바일·PC 모두 왼쪽 정보 / 오른쪽 삽화**를 유지합니다. 해외 300곳과 국내 15곳의 전용 그림, 공통 풍경 10종은 승인된 순천 그림의 손그림 스타일로 통일하고, 가로·세로 구도를 각각 준비해 화면에 맞춰 선택합니다. 활성 이미지 파일은 총 650개입니다. 그림 영역은 카드 아래까지 연결되며, 제목·날짜·인원과 겹치지 않습니다. 좁은 화면의 날짜는 별도 줄로 배치하고, 제목은 모바일 20–24px·PC 24–40px를 유지합니다. [모바일 개선 목업](artifacts/design/20261004/triplog-trip-header-mobile-postcard-20261004.png), [화면 크기별 비교·검증](artifacts/design/trip-header-mobile-20261004/design-qa.md), [도시·공통 풍경 재제작 기록](artifacts/design/trip-scenes-redraw-20261004/design-qa.md), [해외 300곳 제작·검증 기록](artifacts/design/trip-scenes-world-300-20261004/README.md)에 구현 근거를 기록했습니다.

여행 개요 상단은 선택한 [포스트카드 목업](artifacts/design/20261004/triplog-trip-header-postcard-20261004.png)을 기준으로 여행명·D-day·날짜·인원과 목적지 일러스트를 함께 표시합니다. 국내 30곳·해외 300곳의 국가/도시/별칭을 구분하며, 해외 목적지는 모두 각각의 PC·모바일 전용 그림을 사용합니다. [국가별 300곳 목록](artifacts/design/trip-scenes-world-300-20261004/catalog-index.md)은 방문객 순위가 아닌 관광 목적지 편집 목록이며 도시·소도시·섬·지역을 구분합니다. 이번 확장에서는 217곳을 추가하고 기존 공통 그림을 쓰던 해외 25곳도 전용 그림으로 바꿨습니다. 삿포로의 눈축제와 오사카 도톤보리의 글리코 간판 풍경은 유지합니다. 저장된 목적지만 사용하고 여행 제목으로 도시를 추측하지 않습니다. 도시가 불명확하거나 여러 곳이면 공통 그림을 표시하며, 서귀포→제주 같은 명시적 지역 관계는 별도로 처리합니다. 호놀룰루·오아후·하와이는 서로 구분하고, 워싱턴은 D.C.가 명시된 이름에만 전용 그림을 연결합니다. 긴 여행명은 두 줄로 줄이고 전체 이름은 접근성 이름·도움말과 기존 여행 선택 창에서 확인할 수 있습니다.

도시 그림은 현재 화면에 필요한 가로 또는 세로 한 장만 내려받아 최대 48개 이미지 파일을 별도 캐시에 보관합니다. 공통 테마의 가로·세로 20장은 앱에 포함되어, 오프라인에서 아직 받지 않은 도시 그림도 대체 표시됩니다. 여행 데이터나 인증 응답을 그림 캐시에 넣지 않습니다. 도시·별칭·테마의 기준은 `src/app/data/destination-scenes.js`, 선택 규칙은 `src/app/shared/destination-scenes.js`입니다. 격리 미리보기는 `node scripts/preview-trip-header.js`, 검증은 `node scripts/destination-scenes-regression.js`, `node scripts/trip-header-browser-regression.js`, `node scripts/trip-scene-art-browser-regression.js`, `npm run prepare:sync && node scripts/trip-scene-cache-browser-regression.js`입니다.

## 상태와 저장소

TripLOG의 런타임 상태는 전역 `state` 객체입니다. `await saveAndRender()` 또는 `await saveStateSilently()`의 `true`는 기기 저장 완료를 의미합니다. 서버 확인은 별도 저장 상태로 표시합니다. 폼을 닫거나 완료를 알리기 전에 기기 저장 결과를 확인해야 합니다.

- IndexedDB `triplog-collaboration-v2`: 여행 확정본·기기 변경·전송 큐·충돌·복구 사본·입력 초안·첨부 캐시
- `domesticTravelExpensePlanner.trips.v2`: 기존 여행 이관 원본. 협업 버전의 실시간 상태를 기록하는 저장소가 아닙니다.
- sessionStorage `domesticTravelExpensePlanner.activeTripId.v2`: 탭별 현재 여행 ID
- `domesticTravelExpensePlanner.theme.v3`: 선택한 테마
- `domesticTravelExpensePlanner.googleGeocodingApiKey.v1`: 선택적으로 저장한 Google 지오코딩 API 키
- `domesticTravelExpensePlanner.v1`: 기존 단일 여행 이관 원본
- `domesticTravelExpensePlanner.history.v1`: 저장 스냅샷의 localStorage 미러
- IndexedDB `triplog-local-archive` / `travelSnapshots`: 저장 스냅샷의 주 저장소

변경은 기기에 먼저 기록하고 연결이 가능하면 자동 전송합니다. 서버 확인을 받지 못한 변경은 큐에 보존합니다. 새 JSON 백업은 여행·공동 메모·댓글·충돌·전송 대기 명령을 포함합니다. 접근할 수 있는 첨부는 파일 내용으로 포함하며, 불러오지 못한 첨부가 있으면 불완전 백업임을 표시합니다. 복원한 공동 작업 사본은 검토 후 새 공유 여행으로 저장할 수 있습니다.

여행별 `travelCompanion`에는 완료·잠금 일정 ID, 직접 등록한 예약, 시간대와 마지막 시간 조정 기록을 저장합니다. 기존 백업에 이 필드가 없어도 빈 기본값으로 복원합니다. 일정 공유를 끄면 예약 지갑과 진행 상태도 서버 공유 스냅샷에서 제외하며, 시간 조정 되돌리기 기록은 공유하지 않습니다.

로그인 세션은 Supabase SDK의 저장·자동 갱신을 사용합니다. 현재 고정된 auth-js 2.107.0은 갱신 요청의 HTTP 429 및 일부 5xx를 세션 삭제로 처리하므로, `trip-collaboration.js`의 전용 fetch가 **토큰 갱신 요청에 한해** 재시도 가능한 오류로 전달합니다. `Retry-After` 동안 실제 재요청을 제한하고, 별도 토큰 사본이나 수동 저장소 삭제를 사용하지 않습니다. 인증 이벤트 밖에서 여행 동기화를 수행하며, 동일한 세션 확인 요청을 합치고 이전 클라이언트·로그인의 늦은 결과를 무시합니다. 서버가 실제로 인증을 취소하면 재로그인을 요구하고, 기존 계정의 여행·전송 대기 기록·초안은 보관합니다. SDK 버전 변경 시 이 호환 처리와 인증 회귀 테스트를 함께 검토해야 합니다.

## 개발 규칙

- 생성 산출물은 [artifacts 보관 기준](artifacts/README.md)에 따라 한 곳에서 관리합니다. 루트·`docs/`에 새 목업이나 임시 파일을 만들지 않습니다. `npm run artifacts:check`로 배치를 확인하며, 같은 검사를 소스 회귀 테스트에서도 실행합니다.
- UI는 브라우저 전역 구조를 유지합니다. Yjs 번들과 서버용 공통 모델, 오프라인 앱 자산은 `npm run prepare:sync`로 생성합니다.
- `app.js`의 `scriptFiles` 순서가 의존성 순서입니다. 새 모듈은 필요한 전역 함수보다 뒤에, 호출 지점보다 앞에 넣습니다.
- 화면은 해당 기능의 `*-workspace.js`가 소유합니다. 중앙 렌더러는 공통 상태와 현재 페이지를 갱신하고, 정산·준비물 편집은 열린 대화상자를 갱신합니다. 기존 페이지 전체를 숨겨 두고 새 페이지를 덧붙이지 않습니다. `Travel.html`의 `triplogFormSources`는 시작 시 실제 폼을 한 번 옮기는 임시 마운트이며 초기화 후 제거됩니다.
- 경비 계산은 `shared/travel-costs.js`를 사용합니다. 누적 금액과 날짜별 합계는 환불을 차감하고, 항목별 구성은 환불 전 지출과 그 합계를 사용합니다. 환불이 있으면 화면에 구성 기준을 표시합니다. 화면 리포트는 결제일, PDF의 일별 내역은 저장된 여행 일자를 기준으로 묶습니다.
- 카테고리 이름·기본 아이콘·화면별 색상은 `data/expense-categories.js`, 다이얼로그 열기·닫기·포커스 복원은 `ui/dialog.js`, 경비 요약 표시는 `ui/cost-summary.js`에서 관리합니다. 화면별 표현 차이는 명시된 옵션으로 유지합니다.
- 목적지 그림은 `scripts/app-assets.js`가 현재 카탈로그의 파일만 배포 목록에 포함합니다. 도시 그림은 필요할 때 받고 공통 테마만 앱 캐시에 포함합니다. 과거 원본과 목업은 현재 실행 자산으로 추가하지 않습니다.
- 모듈은 `window.TripLog.register("영역.이름", { ... })`로 등록합니다. DevTools에서 `window.TripLog.registry`와 `document.documentElement.dataset.triplogLastModule`로 로드 상태를 확인할 수 있습니다.
- DOM 요소를 추가하면 `Travel.html`의 ID, `src/app/core/runtime.js`의 `els`, 이벤트 연결 위치, 렌더 함수 위치를 함께 맞춥니다.
- 상태 스키마를 바꾸면 `getFallbackState()`, 기존 저장값 정규화/마이그레이션, 샘플 데이터, 저장/복원, 관련 렌더링을 같이 확인합니다.
- 지도 서비스는 `shared/map-links.js`에서 여행 유형으로 선택합니다. 해외는 Google 프레임, 국내는 `services/maps/domestic-map.js`의 OpenStreetMap 지도와 네이버 길찾기 링크를 사용합니다. 주소 후보 조회는 별도로 진행하며 기존 좌표 출처 검증을 유지합니다. 국내 지도 표시에 네이버 클라우드 키나 유료 API는 사용하지 않습니다.
- 캐시 때문에 변경이 보이지 않으면 브라우저 강력 새로고침을 하거나 `app.js`의 `scriptVersion`, `Travel.html`의 CSS/앱 쿼리 버전을 갱신합니다.

## 검증

`npm test`는 PostgreSQL(PGlite)·IndexedDB·독립 기기 동기화 및 기존 기능 회귀 테스트를 실행합니다. `npm run test:browser`는 별도 로컬 서버와 격리된 브라우저 두 개로 화면·오프라인 앱·초안을 확인합니다. Windows에서는 설치된 Edge, 다른 OS에서는 `npx playwright install chromium`으로 설치한 Chromium을 사용합니다.

`npm run test:source`는 앱 모듈 로드 대상, JavaScript·CSS 문법, 브라우저 테스트 등록 누락과 현재 그림의 배포 포함 여부를 검사하며 `npm test`에도 포함됩니다. 새 브라우저 테스트는 `scripts/browser-suites.js`에 등록하고 `scripts/helpers/browser-fixture.js`의 브라우저 실행·서버·테스트 토큰·요청 차단 도우미를 사용합니다. 일반 테스트는 실행기의 로컬 서버를 재사용하며, 별도 응답이 필요한 인증·동기화 시나리오는 자체 목 서버를 유지합니다. 환불 리포트 검증은 `node scripts/report-refund-browser-regression.js`, 수동 환율 검증은 `node scripts/manual-exchange-rate-browser-regression.js`이며 둘 다 전체 브라우저 실행 목록에 포함됩니다.

로그인만 검증하려면 `node scripts/auth-session-browser-regression.js`를 실행합니다. 배포용 Supabase SDK와 가상 인증 서버로 429/5xx/통신 실패, 동시 확인, 오래된 응답, 실제 만료 후 초안 보존, 이메일 복구 링크, 연결 초기화와 여러 탭의 로그아웃을 검사합니다. 실제 계정과 서버 데이터는 사용하지 않습니다.

Edge Function 경계 검증: Deno가 설치된 환경에서 `npm run test:edge`를 실행합니다. CI는 Deno 2.9.6을 사용합니다. 이 실행기는 서버 코드에 명시된 고정 버전 의존성만 해석하고 프런트엔드의 `package.json`·`node_modules`와 분리합니다. Deno의 기본 신규 의존성 대기 정책은 유지합니다. 별도 실행 파일은 `DENO_BINARY`로 지정할 수 있습니다. 배포 파일 생성: `npm run build`.

1. 콘솔 오류 없이 앱이 열리는지 확인합니다.
2. 변경한 페이지와 연동 페이지를 함께 확인합니다. 예를 들어 일정 변경은 지도, 지출 연동, 리포트, 저장 복원을 같이 봅니다.
3. 새로고침 후 여행, 지출, 일정, 정산 설정이 유지되는지 확인합니다.
4. 모바일 폭과 데스크톱 폭에서 탭, 폼, 표, 지도, 모달이 겹치지 않는지 확인합니다.

저장 상태는 상단 버튼에서 확인하고, 지원용 진단 파일을 내려받을 수 있습니다. 개발 중 읽기 전용 확인 예시는 다음과 같습니다. 저장소를 지워 문제를 해결하려 하지 말고 먼저 JSON 백업을 생성하세요.

## 영수증으로 지출 입력

지출 기록의 **영수증으로 입력**에서 촬영하거나 사진을 선택합니다. 한국어+영어, 일본어+영어, 영어 인식을 지원하며, 회전·영역 자르기 후 상호, 결제일, 최종 금액, 통화, 항목, 결제 방식을 검토할 수 있습니다. 인식이 어려우면 사진에서 복사한 글자를 붙여넣을 수도 있습니다.

**지출 폼에 채우기**는 입력값만 반영합니다. 기존 지출 폼에서 **추가/저장**을 눌러야 지출로 저장됩니다. 여행 기간 밖의 결제일은 기록할 여행 일자 또는 사전구매를 직접 선택합니다. 외화는 해외 모드에서 기존 환율로 환산하며, 환불/취소·모호한 총액/통화는 직접 확인합니다.

- OCR은 Tesseract.js 6.0.1 / Tesseract.js-core 6.1.2의 LSTM 엔진과 tessdata_fast 4.1.0으로 브라우저에서 실행합니다. 유료 API나 OCR 서버가 필요하지 않습니다.
- 실행 파일과 한국어·영어·일본어 모델은 `vendor/receipt-ocr/`에서 필요할 때만 로드합니다. 언어 모델은 브라우저에 캐시하고, 인식 창을 닫으면 엔진 메모리를 해제합니다.
- HEIC는 브라우저에서 먼저 열고, 필요할 때만 heic2any 0.0.4로 기기 내 변환합니다. 변환 실패 시 JPG/PNG 안내를 표시합니다.
- 사진과 원문 전체는 저장/업로드하지 않습니다. 저장한 지출에는 중복 확인용 파일 해시와 확인한 결제일만 `receipt` 메타데이터로 추가됩니다. 기존 지출 수정·JSON 내보내기·여행 동기화 시 함께 유지됩니다.
- iPhone 14 Pro의 393×852 화면을 기준으로 구성했습니다. 데스크톱 브라우저의 모바일 크기 검증과 실제 iOS Safari의 성능 검증은 구분해야 합니다.

추출 로직 회귀 검증: `node scripts/receipt-parser-regression.js`. 배포 파일 생성: `npm run build`.
